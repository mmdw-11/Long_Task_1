# 8.29 四组主实验运行手册

本次只保留四组实验：多 Agent 编排稳定性、长期记忆端到端 QA、长期记忆与上下文治理联合、技能闭环。路由、完整记忆大消融、低熵通信和神经符号恢复的实验入口已从 `engine/experiments` 与 `examples/experiments` 移除，避免两天内分散精力。

长期记忆实验按学长的建议采用“先 pilot、再定正式规模”：先跑 2 个 LongMemEval 问题记录，测量每种方法真实时间和 API 稳定性；正式数量由实测时间决定。不要把 Top-5 当成唯一结论，主指标是最终 `QA Acc` 与 `Answer F1`。

## 3. 实验二：长期记忆端到端 QA

### 3.1 先构建 2 条 pilot

```powershell
python examples/experiments/prepare_datasets.py memory `
  --input data/raw/longmemeval/longmemeval_s.json `
  --source longmemeval `
  --output data/processed/longmemeval_pilot_2.jsonl `
  --count 2 --seed 42
```

输出会显示 `questions` 和 `trajectories`。LongMemEval 的评测单位是“问题记录”；每条记录带自己的历史会话。这里的 2 条用于测时和检查，不作为最终结论。

### 3.2 对 2 条 pilot 跑五种方法

以下五条命令共用同一份数据、同一个 QA solver、相同 `top_k=5`。`--fresh` 只在第一次完整 pilot 时使用；中断后不要加它，runner 会读取已有 `rows.jsonl` 并跳过已完成问题。

```powershell
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_pilot_2.jsonl --source longmemeval --backend no_memory --top-k 5 --fresh
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_pilot_2.jsonl --source longmemeval --backend full_context --top-k 5 --fresh
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_pilot_2.jsonl --source longmemeval --backend mem0 --top-k 5 --fresh
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_pilot_2.jsonl --source longmemeval --backend engine --no-llm-judge --top-k 5 --fresh
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_pilot_2.jsonl --source longmemeval --backend engine --top-k 5 --fresh
```

注意：最后两条的输出目录会自动分别叫 `ours_no_judge` 和 `engine`，不会相互覆盖。正式实验中把 `engine` 在论文表里命名为 `Ours Full`。

若 `mem0` 安装、模型下载或 API 调用耗时明显过长，先只保留它在 pilot 与最终较小子集上的结果，并在表格的 `N` 列如实写实际数量。不要用 `--qa-solver extractive` 写论文；它只用于无 API 时检查代码链路。

### 3.3 用 pilot 决定正式样本数

读取五个 `summary.json` 的 `metadata.seconds` 与 `avg_time_ms`，估算正式时间。建议的判断规则：

| 条件 | LongMemEval 正式数量 | LoCoMo 补充数量 |
|---|---:|---:|
| 每方法每题小于 30 秒且 API 稳定 | 30 条问题记录 | 20 条问题记录 |
| 30 到 120 秒 | 20 条问题记录 | 10 条问题记录 |
| 超过 120 秒或 mem0 不稳定 | 10 条问题记录；mem0 仅 10 条 | 5 条问题记录 |

两天内优先保证同一条数据上的五种方法都完成。不要强行跑 100 条而导致只有 Ours Full 有完整结果。

例如 pilot 后决定 `N=20`：

```powershell
python examples/experiments/prepare_datasets.py memory `
  --input data/raw/longmemeval/longmemeval_s.json `
  --source longmemeval `
  --output data/processed/longmemeval_final_20.jsonl `
  --count 20 --seed 42

python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_final_20.jsonl --source longmemeval --backend no_memory --top-k 5
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_final_20.jsonl --source longmemeval --backend full_context --top-k 5
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_final_20.jsonl --source longmemeval --backend mem0 --top-k 5
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_final_20.jsonl --source longmemeval --backend engine --no-llm-judge --top-k 5
python examples/experiments/run_memory_experiment.py --dataset data/processed/longmemeval_final_20.jsonl --source longmemeval --backend engine --top-k 5
```

LoCoMo 作为补充验证，先抽 10 条或 pilot 允许的数量：

```powershell
python examples/experiments/prepare_datasets.py memory `
  --input data/raw/locomo/locomo10.json `
  --source locomo `
  --output data/processed/locomo_memory_10.jsonl `
  --count 10 --seed 42

python examples/experiments/run_memory_experiment.py --dataset data/processed/locomo_memory_10.jsonl --source locomo --backend engine --top-k 5
```

时间允许时，对 LoCoMo 也依次运行 No Memory、Full-Context、mem0、Ours no Judge、Ours Full；优先级低于完成 LongMemEval 的五组对照。

### 3.4 如何看长期记忆结果

每个方法的文件在：

```text
runs/experiments/memory/<source>/<method>/summary.json
runs/experiments/memory/<source>/<method>/rows.jsonl
runs/experiments/memory/<source>/<method>/report.md
```

主表读取 `avg_qa_acc`、`avg_answer_f1`、`avg_tokens`、`avg_time_ms`。检索方法还读取 `avg_hit_at_5`、`avg_mrr`、`avg_evidence_recall`。No Memory 与 Full-Context 没有 Top-K 排序，所以其 Hit@5/MRR 应写 `N/A`，而不是填 0。

`rows.jsonl` 的每一行保存 `prediction`、`expected`、检索指标和 `qa_error`。必须检查是否存在 `qa_error`；有错误的调用要在论文里报告失败数量，不能悄悄删除。`metadata.evidence_metric` 为 `gold_evidence` 时，Hit@5 是官方证据会话命中；为 `answer_text_fallback` 时，仅表示答案文本是否落在检索内容中，不能将其称为严格证据召回。

快速并排查看 summary：

```powershell
Get-ChildItem runs\experiments\memory\longmemeval -Recurse -Filter summary.json | ForEach-Object {
  $s = Get-Content $_.FullName -Raw | ConvertFrom-Json
  [PSCustomObject]@{Method=$_.Directory.Name; N=$s.total; QAAcc=$s.avg_qa_acc; F1=$s.avg_answer_f1; Hit5=$s.avg_hit_at_5; MRR=$s.avg_mrr; Tokens=$s.avg_tokens; TimeMs=$s.avg_time_ms}
} | Format-Table -AutoSize
```

如果需要回应 Top-5 是否不足，只在 pilot 的同一 2 条上将 Ours Full 重跑为 `--top-k 1`、`--top-k 5`、`--top-k 10`，分别给 `--run-name k1/k5/k10`。这是一个敏感性检查，不再运行旧的大消融矩阵。

## 4. 实验三：长期记忆与上下文治理联合

这组实验从 LoCoMo 标准化 QA 中构造 100 条状态保持任务。每条任务保留一段相关历史事实，并叠加原始目标、两条硬约束、中途新增约束、错误干扰、重复风险、预算压力和中断恢复点。它评估后端机制，不是第二组的 LLM QA。

先生成固定数据：

```powershell
python examples/experiments/prepare_datasets.py state `
  --input data/raw/locomo/locomo10.json `
  --output data/processed/locomo_state_100.jsonl `
  --count 100 --seed 42
```

再运行四组对照：

```powershell
python examples/experiments/run_long_task_experiment.py `
  --dataset data/processed/locomo_state_100.jsonl `
  --method all --max-context-tokens 320 --output-dir runs/experiments/long_task
```

输出位置：

```text
runs/experiments/long_task/plain/
runs/experiments/long_task/full_context/
runs/experiments/long_task/memory_only/
runs/experiments/long_task/ours_full/
```

主表使用 `avg_final_task_success`、`avg_goal_retention`、`avg_constraint_compliance`、`avg_memory_use_accuracy`、`avg_drift_rate`、`avg_budget_violation`、`avg_recovery_success`、`avg_tokens`。这里的 `Task Success` 是六项可观察机制条件的合取，因此表注必须写“deterministic backend mechanism evaluation, not LLM QA”。

## 5. 实验四：技能闭环

这组不再使用 SkillEvolBench，而是生成 30 条可控的重复任务：邮件处理、日历安排、旅行规划/报告各 10 条。三组方法是 No Skill、Manual Skill、Ours Skill Loop。

```powershell
python examples/experiments/prepare_datasets.py skills `
  --output data/processed/skill_reuse_30.jsonl `
  --count 30 --seed 42

python examples/experiments/run_skill_experiment.py `
  --dataset data/processed/skill_reuse_30.jsonl `
  --limit 30 --method all --fresh --output-dir runs/experiments/skills
```

结果在三个方法目录中：

```text
runs/experiments/skills/no_skill/
runs/experiments/skills/manual_skill/
runs/experiments/skills/ours_skill_loop/
```

读取 `avg_task_success`、`avg_step_coverage`、`avg_retrieval_hit`、`avg_skill_generation_success`、`avg_validation_pass_rate`、`avg_tokens`。Ours Skill Loop 实际走候选创建、`SkillEvolutionService.validate`、发布、`SkillRetriever.retrieve`；No Skill 不创建技能，Manual Skill 使用每类固定人工技能。这里的 `Task Success` 同样是步骤覆盖代理，不能称为真实 LLM 任务完成率。

## 6. 两天执行顺序与故障处理

第 1 天：完成 workflow 300；下载并规范化数据；跑 LongMemEval 2 条 pilot；确定正式 N；优先完成 LongMemEval 五组。第 2 天：跑 LoCoMo 补充、LoCoMo 状态治理 100、技能闭环 30，并从 `summary.json` 整理表格、从 `rows.jsonl` 选 2 到 3 个失败案例。

中断后的处理：长期记忆和技能 runner 默认读取已有 `rows.jsonl`，直接重复原命令即可续跑；只有确实要清空该方法的旧结果时才增加 `--fresh`。状态治理和 workflow 很快，建议发生异常后使用 `--fresh` 整批重跑。

如果 BGE-M3 或 mem0 初始化失败，先确认 `FlagEmbedding`、`mem0ai`、`qdrant-client` 已安装，并保证模型可下载/可从本地缓存读取。若 mem0 仍不可用，完成其 pilot 后在报告中说明“mem0 因环境限制仅运行 N 条”，不要伪造或用其他方法替代其结果。
