## Placement 启用、训练与回退

三个模式：

- `PLACEMENT_MODE=constrained`：使用安全过滤与预算路径。训练模型就绪时用 Actor 选择；没有模型或策略前向异常时，在同一可行域中使用旧排序。约束无解时明确停止，不退到被禁止的资源。与旧模式相比，不再自动把高复杂敏感任务降级到能力不足的端侧；需拆分任务、调整要求或提供符合条件的资源。
- `PLACEMENT_MODE=auto`：找到已训练的新策略后使用约束路径；否则维持原路由，便于本地兼容。AdaptiveResourceScheduler 的无配置调用保持该模式。
- `PLACEMENT_MODE=legacy`：使用原调度。可作为快速回退；推理 Runner 仍会阻止带有未授权人工复核标记的调用。

Docker Compose 默认设置为 `constrained`；新策略文件通过 `PLACEMENT_POLICY_PATH` 指定容器内可访问路径。回退时将 `PLACEMENT_MODE` 改为 `legacy`，无须删除新模块或恢复数据库。Docker Compose 配置检查已通过。

训练入口：

```powershell
python examples/edge_cloud_scheduler/train_constrained_policy.py --input examples/edge_cloud_scheduler/constrained_training_sample.jsonl --output runs/placement/policy.json --epochs 20
$env:PLACEMENT_MODE = 'constrained'
$env:PLACEMENT_POLICY_PATH = 'runs/placement/policy.json'
```

样例明确标记为合成环境，仅验证训练—保存—加载—决策链路。实际策略须使用受控任务的真实验收反馈训练；本轮未把合成策略设为生产模型，也未声称获得实际任务性能提升。训练数据需提供受控环境中可选动作的反馈，采样使用当前策略；普通单动作历史日志不直接作为在策略训练数据。

每个训练回合包含 `limits` 与 `steps`；每步包含 `profile`、决策时可见的 `estimates` 及仅作为事后反馈的 `outcomes`。后者记录收益、费用、经过时间和成功状态。估计不能从本次事后结果中构造，避免将答案泄漏到决策。训练器在回合结束后更新参数；在线普通请求只记录反馈，不自动学习。

节点配置可设置：

```json
{
  "placement_mode": "constrained",
  "placement_budget": {"fee": 1.0, "time_ms": 10000, "failures": 2},
  "placement_estimates": {"edge": {"fee": 0.1}, "cloud": {"fee": 0.4}},
  "allowed_tiers": ["edge", "cloud"]
}
```

`fee` 的币种/计费单位须在任务中一致，由调用方提供真实费用及决策时费用估计；原 `cost_weight` 只作资源特征，不冒充费用。没有费用测量时，不允许宣称已经满足货币预算；若配置了费用限制，未知计费会阻止后续不确定的调用。`time_ms` 记录已接入推理链的观测时间，并行推理区间去重；它不等于整个工作流所有工具及人工等待的端到端耗时，也不提供最坏截止时间保证。

训练API要求完整终止回合、当前策略采样概率、真实成本和外部提供的质量收益；拒绝旧策略轨迹、确定性部署日志、不完整回合或缺失收益。HTTP成功不会自动写成质量奖励。训练前需由任务验证器补齐 `reward` 和终止标记；无语义质量反馈时仅能采集执行轨迹。

恢复术语：Context Ledger 是任务状态的当前视图，Checkpoint 是该视图连同执行位置、消息状态的恢复版本。实际恢复从图检查点进入 Context Ledger 协调，不把一个JSON文件的加载说成所有外部操作已经回滚。

参考依据：[FActScore](https://aclanthology.org/2023.emnlp-main.741/) 提供按主张检查来源支持的组织方式；[RARR](https://aclanthology.org/2023.acl-long.910/) 提供检索与修订的参考。两者仅作为设计来源，不能用其结果证明本系统已经降低幻觉。
