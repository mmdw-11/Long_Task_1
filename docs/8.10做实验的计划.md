这个项目现在不是“一个简单 Agent demo”，而是一个类 LangGraph 的 Agent 编排后端产品雏形：

核心链路是：

`前端/接口创建 AgentSpec` → `Orchestrator 转成 Node/Graph` → `CompiledGraph 执行节点` → `HookManager 注入记忆/技能/上下文/评估/轨迹` → `RunStore 记录运行` → `SkillEvolutionService 从成功轨迹提取技能` → `validate/publish/rollout` → 下次执行时 `SkillRetriever` 检索技能并注入 Agent 输入。

所以实验不要一上来做“大而全对比”，而要对每个模块分别设计实验，看它到底有没有提升。可以把实验理解成一句话：

同一批任务，固定输入，分别打开/关闭某个模块，和已有框架做对照，看成功率、成本、速度、稳定性有没有变好。

**实验总目标**

证明你的项目相比原生 AgentScope、普通图编排、普通记忆框架、普通路由策略，是否在下面几件事上更好：

1. 多 Agent 编排更清晰、更可控。
2. 长任务上下文不容易漂移。
3. 记忆能提升历史信息复用。
4. 技能闭环能让重复任务越跑越稳。
5. 端-边-云路由能降低成本/延迟，同时保持效果。
6. 后端产品闭环完整：创建工作流、运行、记录、生成技能、审批发布、再次复用。

**第二阶段：图编排模块实验**

对比对象：

1. 原生 AgentScope 顺序/扇出流程。
2. 你的 `StateGraph + Orchestrator`。
3. 可选：LangGraph，如果安装方便。

实验任务：

设计 20-50 个小型工作流：

- 顺序任务：A → B → C。
- 扇出任务：planner → researcher/writer → reviewer。
- 条件分支：根据任务类型走不同 Agent。
- 循环任务：失败后重试，达到上限停止。
- 子 Agent 任务：父 Agent 创建/管理多个子 Agent。

指标：

- 任务成功率。
- 是否能正确走到预期节点。
- 是否能记录完整执行轨迹。
- 是否支持恢复/重试。
- 编排配置复杂度，比如创建同样流程需要多少行代码或多少个接口调用。
- 前端可视化友好度：是否能导出节点和边。

这一组实验主要证明：你的项目不是只会“调用 Agent”，而是具备图结构编排、状态合并、条件路由、循环保护、运行记录这些能力。

**第三阶段：记忆模块实验**

对比对象：

1. 无记忆。
2. 你的 `HybridTieredMemoryStore + HashingEmbeddingModel`。
3. 你的 `HybridTieredMemoryStore + BGE-M3`，这个等服务器或本地模型环境稳定后做。
4. mem0。

数据集建议：

先用自己构造的小数据集，不要一开始追求顶会 benchmark。比如 100 条项目历史记忆：

- 用户偏好。
- 历史决策。
- 已知事实。
- 历史失败经验。
- 项目约束。
- 会议纪要。
- 代码修改记录。

任务形式：

给 Agent 一个问题，看它能不能从记忆里找出正确信息。例如：

- “之前规定技能发布必须经过谁审批？”
- “上次日历 Agent 失败的原因是什么？”
- “这个项目默认路由模型路径在哪里？”
- “某个用户不喜欢什么输出格式？”

指标：

- Recall@K：正确记忆是否出现在前 K 条。
- MRR：正确记忆排第几。
- 回答准确率。
- 检索耗时。
- 写入耗时。
- 存储大小。
- 记忆更新质量：重复记忆是否被合并，过期记忆是否被删除。


**第四阶段：技能演化模块实验**

这是你项目最有特色的部分。

对比对象：

1. 无技能。
2. 手写固定技能。
3. 你的自动候选技能：`create_candidate_from_run`。
4. 你的完整闭环：候选生成 → 校验 → 审批发布 → 检索注入。
5. 不加验证直接发布，作为反面实验。

任务集：

选 3-5 类重复任务，每类 20 个变体：

- 日历会议安排。
- 邮件处理。
- 旅行计划。
- 代码修复计划。
- 长任务报告生成。

实验流程：

第一次运行不带技能，记录结果。

从成功 run 生成候选技能。

执行验证，通过后发布。

第二轮/第三轮重新跑同类任务，看结果是否提升。

指标：

- 成功率是否提升。
- Agent 输出是否更完整。
- 平均执行轮数是否下降。
- 平均 token 是否下降。
- 技能检索命中率。
- 错误复发率是否下降。
- 发布错误技能后的回滚能力。
- 灰度 `rollout_percent` 是否能控制影响范围。

这一组实验能直接对应你参考文档里的 SkillOpt/SkillOS 思路。

你项目目前更像“轻量 SkillOS + 部分 SkillOpt 控制”：

- 有 SkillRepo。
- 有轨迹。
- 有候选技能。
- 有验证。
- 有审批发布。
- 有版本和回滚。
- 有灰度。
- 但还没有真正复杂的自动优化器和大规模 held-out validation。

**第六阶段：端-边-云路由实验**

**第七阶段：端到端产品闭环实验**

这是最后做的，不要一开始做。

目标是证明它像一个真实产品：

用户创建工作流 → 运行任务 → 查看结果 → 生成技能 → 审批发布 → 再次运行 → 系统变好。

实验流程：

1. 创建一个多 Agent workflow。
2. 保存 workflow。
3. 第一次运行任务。
4. 记录 run、events、skill_traces。
5. 从成功运行生成 skill candidate。
6. validate。
7. publish。
8. 第二次运行同类任务。
9. 对比前后结果。
10. 导出系统状态、审计日志、技能版本、运行记录。

指标：

- 链路是否全通。
- API 是否完整。
- 数据是否可追踪。
- 技能是否可回滚。
- 是否有审计。
- 是否能重试。
- 是否能导出实验证据。

**推荐实验顺序**

1. 工程基线实验。
2. 图编排实验。
3. 技能闭环实验。
4. 记忆模块实验。

7. BGE-M3 服务器训练实验。
