# 8.30 平台功能情况

> 后端目录：`Long_Task_1`  
> 前端目录：`Long_Task_1_Fronted`  
> 平台名称：AgentForge 智能体运行平台
> 最近核对：2026-08-31（以当前工作区代码为准）

## 一、当前平台的总体定位

当前项目由以下部分组成，是智能体应用开发与运行平台：

1. 以 `StateGraph` 为核心的多 Agent 图执行引擎。
2. Agent 应用和 Workflow 应用的创建、配置、调试、发布与版本管理。
3. 端、边、云模型连接以及 AUTO 自动调度。
4. 内置工具、MCP、OpenAPI 工具的发现、连接、同步、测试、审批和调用；基础闭环已具备，第三方协议兼容性、隔离和重连仍需深化。
5. Skill 的导入、检索、注入、运行留痕、候选生成、验证、发布、灰度、退役和回滚。
6. 会话短期记忆和受治理的长期记忆库。
7. 后台任务、SSE 运行事件、取消、重试、故障恢复和审计；已有自动化 API 测试，仍需补充长时间生产压测。
8. 用户登录、资源归属、管理员密钥、API Key 和写操作审计。
9. React + TypeScript 可视化控制台。
10. 长任务、技能闭环、记忆、低熵通信、神经符号推理和鲁棒恢复等实验模块。

需要明确：当前系统的主要运行方式仍然是“先创建并连接节点，再执行已经保存或加载的图”。运行中的父 Agent 不会根据任务临时创建任意数量的新 Agent，也不会在执行过程中自动重写整张图。

## 三、当前已经完善的功能

### 3.1 用户、登录与安全

状态：已落地。

- 支持注册、登录、查询当前用户、退出、忘记密码和重置密码。
- 前端启动时会恢复本地 token，并调用 `/api/auth/me` 校验会话。
- 应用、Skill 等资源带用户归属和可见范围，内置资源与私有资源分开处理。
- 可配置 `ADMIN_API_KEY`。配置后，新增、修改、删除类接口必须携带 `X-Admin-Key`。
- 前端会发送 `X-Actor`，后端记录操作人、时间、方法、路径、授权结果和状态码。
- 可创建业务空间 API Key；完整密钥只在创建时展示一次，后端保存哈希。
- 支持 API Key 启用、禁用、删除和审计查看。
- 运行轨迹、工具参数等敏感信息会经过脱敏处理。

### 3.2 应用中心

状态：已落地。

- 支持创建 Agent 应用和 Workflow 应用。
- 应用可以保存名称、描述、头像、系统提示词、模型、提示词变量、工具、Skill、知识库、记忆库和界面配置。
- 应用有草稿和发布状态；配置修改先保存为草稿，发布时执行完整校验。
- Agent 应用提供独立配置与会话调试页。
- Workflow 应用提供可视化编辑器、节点配置、连线、校验、发布和运行。
- 应用广场和模板市场可以作为创建入口。
- 删除应用时会同步处理其绑定的应用工作流等资源。

### 3.3 Agent 编辑器

状态：已落地，真实推理依赖模型配置。

- 可编辑角色说明、系统提示词和模型选择。
- 提示词支持变量定义，并可输入 `/` 快速插入 `${变量名}`。
- 可绑定工具、Skill、知识库和记忆库。
- 工具和 Skill 使用右侧抽屉选择，只在主页面显示当前已选资源。
- 支持短期记忆、长期记忆、上下文轮数、token 预算、滚动摘要、召回数量、唤醒级别、自动写入、去重和敏感过滤配置。
- 调试区支持发送消息、新会话、清空当前短期会话以及查看执行过程。
- 内部系统提示、模型判断信息和工具选择提示不会混入最终用户回答。

### 3.4 Workflow 可视化编排

状态：主要编辑与运行闭环已落地；Knowledge 检索适配、复杂循环语义和生产级脚本隔离仍需深化。

支持的节点类型包括：

- Agent/LLM 节点。
- Tool 节点。
- Knowledge 节点。
- Condition 条件判断节点。
- Intent 模型语义分类节点。
- Script Python/JavaScript 数据处理节点。
- Assign 变量赋值节点。
- Loop 循环节点。
- Batch 批处理节点。
- START 和 END 哨兵节点。
- Loop Start / Iteration End、Batch Start / Batch End 容器边界节点。

编辑器支持：

- 拖拽节点和调整位置。
- 按端口规则连线。
- 条件判断支持有序多分支、组内 AND、组间 OR 和固定“其他”分支；支持字符串、数值、包含、空值等比较运算。
- 意图分类使用已测试成功的模型连接，支持单意图、多意图、分类描述、补充提示词和默认分支；未配置可用模型时检查清单会阻止测试或发布。
- Script 节点支持 Python/JavaScript、输入变量映射、`main(params)` 对象返回、超时、重试和异常策略。脚本在独立子进程中执行，限制继承环境、工作目录、执行时间和输出大小；当前仍不是容器/虚拟机级强隔离。
- Assign 节点支持覆盖、数组追加/合并、数字相加和对象合并，可用于维护工作流或循环中间变量。
- Loop 节点带循环开始和迭代结束子画布，支持固定次数、单/多数组、最短数组长度、最大 100 次、当前元素、索引、提前终止和结果聚合。
- Batch 节点带批处理开始和结束子画布，支持单/多数组、最大处理数、1～10 并发、按输入索引聚合；单项失败默认记录错误并继续其他项。
- Loop/Batch 容器会随内部节点位置动态调整尺寸；拖动容器时内部节点作为整体移动，父子关系会写入工作流图。
- 循环和批处理子画布暂不允许继续嵌套 Loop/Batch，避免无界执行与状态语义冲突。
- 节点级模型、工具、Skill、知识库、记忆库配置。
- Workflow 中的 Agent 节点可搜索并复用已经配置过的 Agent 应用，再在当前节点独立调整。
- 工作流默认模型向未显式选模型的 Agent/LLM 节点继承。
- 检查入口、结束节点、不可达节点、分支连线、模型、工具、知识库、脚本输出、数组变量、容器边界和非法嵌套等错误。
- 草稿保存、发布快照、版本列表和指定版本激活。

旧版单条件、关键词意图、模板脚本及单数组循环/批处理配置会在编辑器读取时映射到新结构，首次保存后升级，已有工作流不需要全部重建。

底层图引擎支持同步/异步函数节点、Agent 节点、子图、普通边、条件边、并行扇出、扇入、循环、共享状态 reducer、流式事件和递归上限。

### 3.5 模型连接与端边云调度

状态：已落地，实际推理由外部模型服务决定。

- 可登记 OpenAI-compatible 模型连接。
- 连接信息包含名称、Provider、Base URL、模型 ID、API Key、端/边/云层级、启用状态和测试状态。
- API Key 不会在查询接口中原样返回。
- 模型测试会先请求 `/models`，再请求 `/chat/completions` 验证基本推理。
- 修复了小输出预算可能全部消耗在思考过程、导致连接误判失败的问题：测试时关闭 thinking，并把 `max_tokens` 提高到 32。
- 每个端、边、云层级只能有一个 AUTO 默认连接。
- AUTO 只有在端、边、云三个默认连接都已启用、配置完整且测试成功时才允许应用发布或运行。
- 固定模型连接必须存在且处于 runnable 状态。
- 正被应用或工作流节点引用的模型连接禁止删除。
- 运行时通过 `AdaptiveResourceScheduler → ExecutorRegistry → ResilientInferenceRunner` 选择执行器，并支持失败重试或向其他层级回退。

### 3.6 工具、MCP 与 OpenAPI

状态：已落地；第三方工具依赖服务可用性。

- 工具目录支持创建、查询、更新、删除、启停和测试。
- MCP 广场支持 OneKey/模板式安装。
- 支持自定义 MCP Server 连接、测试、同步工具和删除连接。
- 支持把 MCP 绑定到具体 Agent，并选择该 Server 暴露的工具。
- 支持 OpenAPI 文档导入；一个 OpenAPI 文档会按 operation 拆成多个工具。
- 工具运行支持参数校验、风险分级、审批请求、批准、拒绝和审计。
- 支持低风险工具自动执行，高风险工具暂停等待人工审批。
- 已有本地演示工具，包括计算器和邮件类 MCP 演示链路。
- 计算器支持全角运算符，并限制为安全四则运算，避免直接执行任意表达式。
- 修复了内部 todo 标识中类似 `-1` 的内容被错误识别为用户算式的问题。

### 3.7 Skill 闭环治理

状态：已落地。

- 支持手工创建 Skill。
- 支持从 Git 仓库、ZIP 和单个 Markdown 文件导入。
- ZIP 导入有路径穿越、文件数量、总大小和扩展名校验。
- 重复导入相同 Skill 会进行去重，不再生成多条同名记录。
- Skill 仓库保存 manifest、正文、版本、状态、验证报告、来源和可见范围。
- 在线运行前根据任务、节点和元数据检索相关已发布 Skill，并注入节点 Prompt。
- 运行过程中记录检索、注入、使用、结果和脱敏证据。
- 可以从一次有效运行及其轨迹生成候选 Skill。
- 生命周期为：`candidate → validated → published`，也支持 rejected、retired。
- 支持人工审批发布、灰度比例、版本历史和版本回滚。
- 灰度通过稳定哈希决定任务是否使用新版，避免新版直接全量替换稳定版本。

Skill 自动演化属于离线治理链路，不是每个 Agent 执行结束后立即自动改写线上 Skill：

```text
运行轨迹 → 显式生成候选 → 验证 → 审批 → 灰度/发布 → 后续运行检索复用
```

### 3.8 短期会话与长期记忆

状态：已落地，语义合并能力仍可继续增强。

- 每个应用可创建多个独立会话。
- 会话持久化保存用户消息、助手回复、滚动摘要和 token 估算。
- 清空只影响当前会话，不删除长期记忆。
- `context_rounds` 控制携带最近多少轮完整对话，0 表示不携带历史。
- 超出 token 预算时优先保留当前问题和最近两轮，更早内容进入滚动摘要。
- 每个应用最多指定一个可写主记忆库，其余绑定库为只读参考库。
- 主库和参考库都参与检索；新长期记忆只允许写入主库。
- 每个记忆库内部有 WORKING、TASK、PROJECT、GLOBAL 四级作用域。
- 自动沉淀只进入 PROJECT；GLOBAL 由人工提升。
- 自动写入会进行完全相同内容去重和密钥、Token、密码等敏感信息拦截。
- 支持记忆预览、搜索、审计、复制规则、人工新增、提升、删除、撤销自动写入和清空。
- 审计会记录 added、ignored、blocked 等动作及原因。

### 3.9 知识库与数据资源

状态：资源管理和工作流挂载已落地；真实检索执行仍是待深化能力。

- 应用和节点可绑定知识库 ID。
- Knowledge 节点当前在运行时安全透传上游输入，并返回空文档列表及 `retrieval_enabled: false` 标记，保证占位能力不阻断工作流；尚未完成文档切分、Embedding、向量召回和引用返回。
- UI 设计、组件、知识库、数据连接、评测、观测和权限页面共用资源 CRUD 框架。
- 组件广场支持浏览和安装可复用组件。
- 对接真实向量库、数据库、观测平台或评测引擎时，仍需在对应资源适配器中补充实际连接逻辑。

### 3.10 运行中心与可观测性

状态：已落地。

- 支持同步 `/api/run` 和后台 `/api/runs` 两种运行方式。
- 后台运行状态包括 created、queued、running、succeeded、failed、cancel_requested、canceled。
- 支持查询运行列表、详情、增量事件和 SSE 实时事件流；工作流测试窗口会实时更新当前运行节点。
- 事件包括节点开始、节点结束、工具请求、工具结果、路由、错误、恢复和最终结果。
- Workflow 测试采用文本对话形式，不要求用户填写专业 JSON input。
- 测试窗口按实际编排/执行顺序展示节点状态、耗时、路由、循环轮次、批次索引、父容器以及节点输入输出；执行过程区域可滚动查看完整内容。
- 最终回答支持安全的 Markdown 渲染，包括标题、粗体、列表、引用、代码块、行内代码和 HTTP(S) 链接；原始 HTML 仅按文本展示，不执行注入内容。
- Agent 调试同样以任务对话形式显示 Agent 切换、工具调用、过程信息和最终答案。
- 支持协作式取消：下一事件边界检查取消状态后安全停止。
- 支持重试并创建新的 Run，保留 `parent_run_id`、`retry_count` 和来源。
- 支持人工批准或拒绝待审批工具调用。
- 系统指标统计应用、工作流、运行状态、Skill 和工具数量。
- 支持导出系统快照，方便备份、迁移和排查。

运行事件中的子流程事件带 `parent_node_id`，批处理事件带 `batch_index`，循环事件带 `iteration`；批处理内部子画布事件会合并进主 Run，便于检查具体失败项。

### 3.11 故障恢复、上下文与执行基础设施

状态：已落地。

- 图执行失败会生成 `FailureRecord` 并汇总到 `FailureTrace`。
- 支持重试、跳转、降级和中止等恢复决策。
- Context Ledger 记录当前任务上下文、todo、预算、漂移、检查点和压缩结果。
- 支持父子 Agent 上下文隔离和父级结果校验元数据。
- 通信模块支持结构化消息、压缩和低熵通信实验。
- 推理模块支持神经符号 Reasoner、Validator 和约束验证。
- 调度模块包含端边云策略、监控、学习门控和实验性高级训练模块。
- 安全模块提供审计和脱敏。

### 3.12 实验体系

状态：实验代码和结果文档已形成，实验结论与生产平台能力应分开理解。

- 长任务实验：比较不同上下文、记忆、技能和工作流策略。
- 技能闭环实验：验证技能提取、复用和成功率变化。
- 记忆实验：验证长短期记忆、召回和上下文压缩。
- 低熵通信与时态证据记忆实验。
- 神经符号协同推理与鲁棒故障恢复实验。
- 支持本地数据集、离线模式、真实 API 模式、报告输出和实验产物归档。

## 四、平台完整运行流程

### 4.1 启动流程

推荐从前端目录运行：

```powershell
cd D:\Pro\Agent-Graph\Long_Task_1_Fronted
npm run dev
```

实际流程为：

```text
执行 scripts/dev.mjs
  ↓
检查 http://127.0.0.1:8000/api/system/status
  ↓
后端未启动时，从相邻 Long_Task_1 目录执行 python -m engine.server
  ↓
等待 FastAPI 健康接口
  ↓
启动 Vite
  ↓
浏览器访问 http://localhost:5173
  ↓
Vite 将 /api/* 代理到 http://127.0.0.1:8000
```

也可分别启动：

```powershell
cd D:\Pro\Agent-Graph\Long_Task_1
python -m engine.server

cd D:\Pro\Agent-Graph\Long_Task_1_Fronted
npm run dev:web
```

### 4.2 用户进入平台

```text
打开前端
  ↓
读取 localStorage 中的 authToken
  ↓
有 token：调用 /api/auth/me 恢复用户
无 token 或校验失败：显示登录/注册页
  ↓
登录成功后保存 token、用户邮箱和后端地址
  ↓
进入快速开始/应用中心
```

### 4.3 创建并运行 Agent 应用

```text
创建 Agent 应用
  ↓
填写名称、描述、头像、系统提示词和提示词变量
  ↓
选择固定模型连接或 AUTO
  ↓
绑定 Tool / MCP / Skill / Knowledge / Memory
  ↓
配置短期和长期记忆策略
  ↓
保存草稿
  ↓
在调试区创建或复用 conversation_id
  ↓
输入用户问题
  ↓
后端读取短期会话、滚动摘要和长期记忆
  ↓
检索已发布 Skill，形成运行 Prompt
  ↓
按模型选择进行固定连接或端边云调度
  ↓
模型判断是否调用工具
  ↓
低风险工具直接执行；高风险工具等待审批
  ↓
工具结果回送模型，模型继续推理
  ↓
过滤内部提示，输出自然语言最终答案
  ↓
保存会话消息、运行事件、Skill 轨迹和记忆审计
  ↓
发布前再次校验模型和资源配置
```

### 4.4 创建并运行 Workflow 应用

```text
创建 Workflow 应用
  ↓
进入可视化编辑器
  ↓
添加 START、Agent、LLM、Tool、Knowledge、Condition、Intent、Script、Assign、Loop、Batch、END 等节点
  ↓
配置节点参数、模型、变量和绑定资源；Loop/Batch 在子画布中连接内部节点
  ↓
连接普通边或带 route 的条件边
  ↓
保存草稿
  ↓
校验入口、出口、连通性、分支、脚本、容器、必填资源和模型可用性
  ↓
发布：生成不可变发布版本快照
  ↓
发起运行
  ↓
WorkflowStore 读取指定版本图
  ↓
Orchestrator.from_dict() 恢复节点和边
  ↓
WorkflowNodeRuntimeFactory / AgentRuntimeFactory 将 AgentSpec 转成对应的可执行 Node
  ↓
StateGraph.compile() 生成 CompiledGraph
  ↓
按 Pregel 超步执行当前 frontier；同一超步节点可并行
  ↓
各节点输出合并到 GraphState
  ↓
普通边/条件路由决定下一批节点
  ↓
发生错误时记录 FailureTrace，并由恢复策略决定重试、跳转、降级或终止
  ↓
到达 END 或无后继节点，输出 final 状态
```

### 4.5 工具调用和审批流程

```text
Agent Prompt 中注入可用工具说明
  ↓
模型输出工具调用意图和参数
  ↓
ToolRuntime 校验工具存在、启用状态和参数
  ↓
判断风险等级
  ├─ 低风险：执行适配器/MCP/OpenAPI operation
  └─ 高风险：Run 产生 approval_required 事件并暂停
                 ↓
              前端批准或拒绝
                 ↓
              执行或返回拒绝结果
  ↓
工具结果写入运行事件并回送 Agent
  ↓
Agent 继续生成最终回答
```

### 4.6 Skill 演化流程

```text
在线运行前检索 published Skill
  ↓
按任务稳定哈希应用灰度规则
  ↓

  ↓
执行中记录 SkillTrace
  ↓

  ↓
SkillEvolutionService 读取 Run 和 Trace
  ↓

  ↓
验证
  ↓
人工批准发布
  ↓

  ↓

```

### 4.7 记忆运行流程

```text
收到 app_id、conversation_id 和本轮输入
  ↓
读取最近 context_rounds 轮对话
  ↓
估算 token，超预算则压缩旧消息为 rolling summary
  ↓
从主库和参考库检索长期记忆
  ↓
把短期上下文、摘要和长期记忆分别注入 Prompt
  ↓

  ↓
保存本轮用户与助手消息
  ↓

  ↓

  ↓
符合规则时写入主库 PROJECT 层，否则记录 ignored/blocked
```

### 4.8 草稿、发布与回滚流程

应用工作流已改为“编辑不产生发布版本”：

```text
连续编辑和保存
  ↓
save_draft：更新草稿，版本号不增长
  ↓
点击发布
  ↓
执行模型、图结构和资源校验
  ↓
publish：生成发布快照，版本号增长
  ↓
选择历史版本回滚
  ↓
activate_version：激活旧发布快照，不伪造新的历史版本
  ↓

```

普通独立工作流仍保留“保存归档旧版、回滚生成可审计新版本”的兼容行为。

## 六、部分遇到的问题与解决方法

### 6.1 默认节点只会 Echo，不是真实模型

问题：早期 REST 编排使用默认 `echo_node_factory`，节点只是复读输入，容易让人误以为已经调用真实大模型。

解决：新增 `AgentRuntimeFactory`，把 Agent 配置、任务、上下文、Skill 和记忆组合成 Prompt，经调度器和执行器调用真实模型；模型不可用时保留 Echo 作为容错降级。同时在运行结果中记录 `executor`、`model`、`success` 和 metadata，便于判断是否真的命中模型。

检查方式：若结果显示 `LocalEchoExecutor / local-echo`，说明链路完成但真实模型未成功使用，不能把它当作真实推理结果。

### 6.2 本地 Qwen 明明存在，却没有被运行时发现

问题：本地下载模型不等于服务端点已经启动并被当前进程配置。运行时依赖 Base URL、模型 ID 和健康测试，不会仅靠磁盘模型目录自动发现。

解决：把模型统一纳入模型连接管理，显式配置 Base URL、模型 ID 和层级，执行连接测试；失败时允许回退，保证平台不崩溃。后续验证必须查看实际 executor/model，不能只看任务状态 succeeded。

### 6.3 模型连接测试误报失败

问题：部分推理模型会先输出 reasoning，原测试 `max_tokens=8` 太小，预算可能被思考过程耗尽，虽然服务可用却拿不到预期的 `OK`。

解决：连接测试请求增加 `thinking: disabled`，并把 `max_tokens` 提升到 32；测试同时检查模型列表和聊天推理两个接口。

### 6.4 AUTO 模型含义不清，可能发布后才发现无可用模型

问题：旧逻辑把空模型、auto、device、edge、cloud 混用，AUTO 没有严格保证三层资源都有可用默认连接。

解决：建立共享 `ModelConnectionStore`，每层只允许一个 `auto_default`；新增 `/api/model-connections/auto-status`；发布和运行前校验端、边、云默认连接全部 runnable。为兼容旧数据，真正的空字符串仍暂时保留旧开发回退行为，用户显式保存为 AUTO 后执行严格校验。

### 6.5 正在使用的模型连接可能被误删

问题：删除模型连接后，应用或工作流节点会留下悬空 ID。

解决：删除前遍历应用和工作流节点；若存在引用，返回明确的应用/节点名称并阻止删除。

### 6.6 真实模型回答被误判为回退

问题：前端和后端曾根据回答文字特征判断是否为 fallback，导致真实模型的正常回答被折叠或标错。

解决：改为依据结构化 executor、model、success 和 metadata 判断；模型处理信息在调试页面折叠展示，不污染最终答案。

### 6.7 内部 Prompt 和运行判断进入最终回答

问题：模型选择、工具判断、内部 todo、系统提示词等调试文本曾被拼进用户可见回答。

解决：区分内部事件、工具事件和最终 assistant 内容；在后端净化消息，在前端过滤内部事件，并仅把最终自然语言内容放到答案区。

### 6.8 全角算式无法调用计算器

问题：中文输入常出现 `（ ） × ÷ ＋ －` 等全角符号，原检测和解析只认识半角字符。

解决：在检测与执行前统一归一化全角字符，再使用受限的安全算式解析器执行。

### 6.9 内部 todo ID 被误识别成算式

问题：内部上下文中的 `todo-1` 或相似片段可能被正则截取为 `-1`，从而在“生成会议纪要模板”这类非计算任务中错误调用计算器。

解决：计算器意图判断只分析用户输入，不扫描内部 Prompt/todo ID；增加自动化回归测试，确保非数学任务不会产生 `tool_result`。

### 6.10 MCP 合并时前后端能力不一致

问题：合并远程 MCP 更新时，后端新增了发现、导入、同步和执行接口，前端分支又有自己的页面布局，直接选一侧会丢功能或丢界面。

解决：后端保留 MCP 发现、连接、同步、测试和执行；前端保留当前布局，同时把 MCP、OpenAPI、同步和测试入口补入工具抽屉和管理页。

### 6.11 工具和 Skill 全量平铺，配置页过于拥挤

问题：智能体配置页直接显示全部工具和全部 Skill，用户难以区分“平台已有”和“当前 Agent 已选”。

解决：主页面只显示已选择项；添加操作统一放进可搜索、可分类的右侧抽屉；外部导入后自动刷新并选中新资源。

### 6.12 Skill 重复上传生成重复记录

问题：相同 ZIP/Markdown 多次上传会生成多个同名 Skill。

解决：导入时按稳定标识和内容进行查重；统一 ZIP 与 Markdown 文件入口；补充重复上传隔离测试。

### 6.13 ZIP 导入存在安全风险

问题：直接解压用户 ZIP 可能出现路径穿越、超大文件、文件炸弹和不允许的扩展名。

解决：导入器限制解包路径、文件数量、单项/总体大小和扩展名，并在真正保存 Skill 前执行 manifest 校验。

### 6.14 Skill 模型命名在合并后不一致

问题：不同分支同时存在 `Skill`、`SkillManifest`、`SkillRecord.manifest` 以及旧版 publish/retire/rollback 调用形态，合并时容易冲突。

解决：暂时加入兼容入口，让旧对象和旧调用仍可读取/保存，避免已有数据和测试立即失效。该兼容层是迁移措施，不应继续扩散；后续应统一领域模型后分阶段删除无效回退。

### 6.15 工作流每次编辑都增长版本

问题：应用编辑器频繁自动保存，如果每次保存都归档版本，会产生大量没有发布意义的历史版本，回滚列表也无法代表真实上线版本。

解决：应用工作流新增 `save_draft`、`publish` 和 `activate_version`：草稿编辑不增长版本，发布才创建快照，回滚只激活历史发布版本。并处理首次发布时旧版未发布归档文件的兼容迁移。

### 6.16 Agent 应用修改与底层工作流不同步

问题：Agent 应用表单改了名称、提示词、模型或绑定资源，但其单节点工作流可能仍保留旧配置；回滚工作流后应用展示也可能不同步。

解决：保存 Agent 应用时同步更新入口 Agent 节点；激活历史版本时再把入口节点配置回写应用记录。

### 6.17 Workflow 默认模型没有传给空模型节点

问题：工作流应用虽然选择了默认模型，但节点 model 为空时运行时仍可能落到旧回退。

解决：恢复工作流图时，将应用默认模型继承给没有显式模型的 Agent/LLM 节点；显式选择的节点模型优先。

### 6.18 知识库节点被发布校验无条件阻止

问题：旧校验固定返回“检索运行能力尚未接入”，即使节点已经绑定知识库，也会让包含 Knowledge 节点的工作流无法验证其他编排功能。

当前解决：删除无条件硬阻断，改为检查 Knowledge 节点是否绑定有效知识库；运行时采用显式标记的安全占位结果，不伪装成真实召回。后续仍需接入文档解析、Embedding、向量检索、重排和来源引用，完成后才能把该节点标记为完整检索能力。

### 6.19 长短期记忆概念混淆

问题：曾把 WORKING/TASK/PROJECT/GLOBAL 误解为四个独立记忆库，也没有区分哪个库可以写入。

解决：明确四级是“单个库内部的作用域”；应用可绑定多个库，但最多一个主库可写，其余是只读参考库；检索多库、沉淀只写主库 PROJECT。

### 6.20 长期记忆无条件写入导致污染

问题：早期设计可能把每个节点输出都写入长期记忆，造成临时内容、错误结果和敏感信息污染。

解决：每轮完成后只从用户输入识别稳定偏好、长期要求和项目决策候选；增加自动写入开关、主库限制、去重、敏感过滤和完整审计；GLOBAL 只允许人工提升。

### 6.21 会话上下文无限增长

问题：完整携带所有历史对话会迅速耗尽模型上下文窗口，并增加费用和漂移。

解决：增加 `context_rounds` 和 token 预算；优先保留当前问题和最近轮次，更早消息压缩成滚动摘要，并记录 `context_usage` 供调试。

### 6.22 前端会话接口与旧后端版本不兼容

问题：前端先升级到会话记忆后，连接未重启或旧后端时 Conversation API 不存在，可能导致整个 Agent 编辑器不可用。

解决：把会话能力做成渐进增强：核心 Agent 编辑功能仍可打开；会话接口不可用时给出明确提示，而不是让整个页面崩溃。后端功能修改后仍应重启服务，确保路由加载最新代码。

### 6.23 哈希路由切换和登录态竞态

问题：页面 hash、编辑器 hash 与 React 状态可能不同步；登录成功后旧的 `/auth/me` 请求也可能晚到并错误清空新 token。

解决：统一监听和写入 hash；Agent/Workflow 编辑器使用独立 hash；认证恢复使用请求序号，只有当前请求可以修改登录态，登录成功后使旧请求失效。

### 6.24 工作流取消不能强制终止 Python 线程

问题：FastAPI BackgroundTasks 中直接杀死运行线程风险较高，可能破坏状态和资源释放。

解决：采用协作式取消，把状态改为 `cancel_requested`，图执行在下一个事件边界检查并安全停止，最后标记 canceled。界面需提示取消可能不是瞬时完成。

### 6.25 JSON 文件持久化的并发与生产风险

问题：当前工作流、运行、应用、Skill、工具、会话、记忆等主要持久化为 JSON 文件。它适合本地演示和可审计原型，但不适合多实例、高并发和复杂查询。

当前解决：按资源分目录存储、写入时保持结构化记录、版本归档并加测试隔离。

后续方案：引入正式数据库和对象存储，增加事务、唯一约束、索引、并发控制、备份迁移与多租户隔离。

### 6.26 工作流逻辑节点只有占位配置

问题：早期 Condition 只有一条判断，Intent 只做关键词包含，Script 只替换 `{{input}}`，Batch 直接透传整个数组，无法表达真实业务工作流。

解决：引入条件分支/条件组、模型语义意图分类、受限 Python/JavaScript 脚本、变量赋值、多数组循环以及并发批处理子图。旧字段通过读取迁移函数映射到新配置，后端仍保留旧字段兼容入口。

### 6.27 循环和批处理容器只有外观，没有完整执行层级

问题：仅在前端 metadata 中保存位置和父子关系，运行时无法可靠判断哪些节点属于循环或批处理，容器内部事件也无法关联父节点。

解决：AgentSpec 的 `children` 和节点 config 会保存父子关系；Loop/Batch 自动创建边界节点，批处理运行时按子图和受控并发执行，每项状态独立，结果按原索引排序。运行事件补充 `parent_node_id`、`iteration`、`batch_index`、输入和输出。

### 6.28 测试最终回答直接显示 Markdown 源码

问题：模型返回的 `**粗体**`、列表和代码块曾以源码形式展示，阅读体验较差。

解决：新增无外部依赖的安全 Markdown 渲染组件，支持常见块级和行内语法，只允许 HTTP(S) 链接，原始 HTML 保持转义文本，从而兼顾显示效果和注入安全。

14. 实现真正的动态组织能力时，应作为受控扩展：父 Agent 先生成计划，经权限、预算、最大节点数和人工确认后再修改图，而不是无约束现场创建 Agent。
15. 将 Python/JavaScript 工作流脚本迁移到容器、受限账户或专用沙箱服务，补充 CPU、内存、系统调用和网络级隔离；当前子进程限制适合开发验证，不应视为多租户强安全边界。
16. 为 Loop/Batch 增加更完整的嵌套子图调试、失败重试策略、断点恢复和大数组背压；当前明确禁止嵌套 Loop/Batch。
17. 为意图分类增加结构化输出兼容、置信度阈值、分类评测集和模型降级策略；当前无可用模型时会阻止测试和发布。

## 九、结论

截至 8 月 30 日，平台的主闭环已经形成：

```text
用户登录
  → 创建 Agent/Workflow 应用
  → 配置模型、工具、Skill、知识和记忆
  → 调试与发布
  → 图执行与工具审批
  → 运行观测、取消和恢复
  → 记忆沉淀与 Skill 演化
  → 版本回滚和安全审计
```

当前最值得优先处理的不是继续增加页面数量，而是把“真实模型命中、数据库持久化、资源适配器、完整权限、任务队列和端到端验收”做扎实。尤其要持续区分“运行成功”和“真实模型成功”：只有运行记录明确显示期望的 executor 与 model，才能确认端边云推理链路真正生效。

补充现状：MCP、OpenAPI 和工具基础调用链路已经存在，但协议覆盖、连接隔离、重连和第三方兼容性仍需持续完善。模型连接、Skill、工具调用、会话记忆和长期记忆已形成基础闭环；工作流应用也已完成测试对话、检查清单、版本管理、观测，以及 Condition、Intent、Script、Assign、Loop、Batch 等逻辑节点的实质改造。当前后续重点是生产级安全隔离、真实知识检索、数据库与任务队列、端到端测试和细节体验，而不是继续把现有能力描述为“尚未修改”。
