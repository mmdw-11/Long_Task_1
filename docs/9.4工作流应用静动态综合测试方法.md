可以。下面给你一个“完整冒烟测试”例子：会覆盖普通 Agent、智能体团队、静态逻辑、动态逻辑，以及资源挂载、Handoff、目标检查、恢复边界和结果汇聚。

先准备资源：

- DeepSeek 模型连接：确保“已测试成功”。
- 创建知识库：`赛题与论文资料库`，上传赛题 PDF、你的重点文档或论文资料；确认状态为“就绪”，且已有切片。
- 准备一个已发布 Skill：例如 `学术证据检索规范`。
- 准备一个低风险工具：例如内置的“当前时间”。它主要用于验证“工具可用性”指标，不一定会在本任务中被调用。

## 一、画布要拖入的节点

外层从左到右：

```text
开始
  ↓
任务规划器
  ↓
脚本
  ↓
意图分类
  ↓
条件判断
  ├─ 复杂研究 → 变量赋值 → 智能体团队 → 恢复边界 → 结果汇聚器 → 目标检查器 → 结束
  └─ 其他请求 → 结束

恢复边界的“恢复”出口 → 兜底说明 Agent → 结果汇聚器

目标检查器的“继续”出口 → 补救 Agent → 结束
```

团队内部只拖入成员，不画成员间静态连线：

```text
智能体团队
  ├─ 任务接待与分流 Agent
  ├─ 资料检索 Agent
  └─ 方案综合 Agent
```

## 二、逐个节点如何配置

### 1. 开始

保持默认即可。

### 2. 任务规划器

- 节点名称：`全局任务规划`
- 节点描述：`把复杂研究目标拆解为可追踪的子任务`
- 规划模型：选择你的 DeepSeek
- 规划方式：`按目标自适应拆分`
- 高级配置保持默认：

```text
输入字段：input
计划输出字段：task_plan
最大子任务数：8
```

### 3. 脚本

- 节点名称：`任务标准化`
- 节点描述：`保留原始任务并写入测试类型和验收标准`
- 语言：Python
- 输入变量保持：

```text
名称：input
路径：input
```

- 脚本代码填：

```python
def main(params):
    text = str(params.get("input", ""))
    return {
        "normalized_task": text,
        "task_type": "dynamic_multi_agent_research",
        "acceptance_criteria": [
            "给出动态路由依据",
            "包含资料证据或知识库信息",
            "给出可执行的架构与测试计划"
        ]
    }
```

- 输出字段：`script_output`

注意：这个脚本执行后，后续节点要从 `input.normalized_task` 取原始任务。

### 4. 意图分类

- 节点名称：`任务类型识别`
- 节点描述：`识别是否属于复杂多智能体研究任务`
- 分类模型：DeepSeek
- 分类模式：`单意图`
- 输入变量：`input.normalized_task`

创建两个意图：

| 意图名称 | 描述 | 路由标识 |
|---|---|---|
| 复杂研究任务 | 涉及赛题、论文、架构设计、智能体协作、验证方案 | `research` |
| 普通咨询 | 简单问答、单步解释、无需团队协作 | `simple` |

补充提示词填：

```text
当任务涉及多智能体、动态路由、比赛方案、论文、架构设计、
知识库检索、低熵通信、时态记忆或故障恢复时，必须归类为“复杂研究任务”。
```

连线：

```text
任务标准化 → 任务类型识别
research → 条件判断
simple → 结束
```

### 5. 条件判断

- 节点名称：`复杂任务二次确认`
- 节点描述：`只允许包含多智能体关键词的任务进入自治团队`

配置一个分支：

```text
字段：input.normalized_task
运算符：包含
值：多智能体
```

- 分支路由：`branch_1`
- 默认路由：`default`

连线：

```text
branch_1 → 变量赋值
default → 结束
```

### 6. 变量赋值

- 节点名称：`注入团队任务`
- 节点描述：`把标准化任务写入团队路由上下文`

新增赋值规则：

```text
目标变量：route_context
操作：set
来源：input.normalized_task
```

连线：

```text
复杂任务二次确认 → 注入团队任务 → 智能体团队
```

## 三、智能体团队配置

团队节点：

- 名称：`动态异构研究团队`
- 团队职责描述：

```text
根据当前子任务、成员能力、模型提示词、工具、Skill、知识库、
历史成功率、成本、时延与失败风险，动态选择成员并允许自主 Handoff。
```

- 输入字段：`route_context`
- 输出字段：`team_result`

### 团队成员 1：任务接待与分流 Agent

拖入团队内部。

基础配置：

- 名称：`任务接待与分流 Agent`
- 职责描述：

```text
理解复杂任务，识别当前缺失能力；需要赛题资料、论文证据或知识库检索时发起 Handoff。
```

- 模型：DeepSeek
- 系统提示词：

```text
你负责理解任务并判断下一步需要什么专业能力。

如果任务需要赛题资料、论文证据、知识库检索或技术事实核验，
不要自行编造。请在回答最后单独输出一行 JSON：

{"status":"needs_handoff","remaining_task":"需要完成的下一步任务",
"required_capabilities":["知识库检索","论文证据"],
"reason":"为什么需要转交",
"context_summary":"已获得的上下文摘要"}

如果任务已经完成，直接给出结果，不输出 JSON。
```

团队成员卡片配置：

```text
允许动态调用：开启
优先级：3
能力标签：需求理解、任务分流、Handoff、任务拆解
```

### 团队成员 2：资料检索 Agent

拖入团队内部。

基础配置：

- 名称：`资料检索 Agent`
- 职责描述：

```text
从赛题资料库和已挂载 Skill 中检索论文、赛题要求和技术证据，
输出可追溯的事实与实现依据。
```

- 模型：DeepSeek
- 系统提示词：

```text
你是资料检索专家。优先使用已挂载知识库中的赛题资料和论文证据。
输出：关键证据、证据来源、可采用技术、局限性。

若已获得资料但需要形成最终架构方案，请在回答最后输出：
{"status":"needs_handoff","remaining_task":"基于检索证据形成完整架构与测试计划",
"required_capabilities":["系统架构设计","方案整合"],
"reason":"检索完成，需要方案综合",
"context_summary":"检索到的核心证据摘要"}
```

挂载资源：

```text
工具：当前时间
Skill：学术证据检索规范
知识库：赛题与论文资料库
```

团队成员卡片配置：

```text
允许动态调用：开启
优先级：1
能力标签：知识库检索、论文证据、赛题分析、技术调研
```

### 团队成员 3：方案综合 Agent

拖入团队内部。

基础配置：

- 名称：`方案综合 Agent`
- 职责描述：

```text
综合任务目标和检索证据，输出动态异构群体智能架构、
关键创新点、实现步骤和测试计划。
```

- 模型：DeepSeek
- 系统提示词：

```text
你是系统架构与方案整合专家。基于团队已提供的上下文，
输出可落地的技术方案。

必须覆盖：
1. 动态路由与资源感知选择；
2. 低熵通信；
3. 时态证据记忆；
4. 神经符号约束与故障恢复；
5. 可验证的测试方案。

若信息足够，直接输出最终方案，不再请求 Handoff。
```

团队成员卡片配置：

```text
允许动态调用：开启
优先级：0
能力标签：架构设计、方案整合、测试设计、故障恢复
```

### 团队协作方式

```text
首轮协作：仅选择一位成员
本轮选择数：1
最大并发：1
允许成员发起自主 Handoff：开启
最大 Handoff 次数：2
```

### 团队目标、恢复与输出

```text
目标检查：自动
成员失败时自动选择备用成员：开启
团队内结果汇聚：综合生成
```

高级设置：

```text
拓扑策略：任务自适应稀疏
最大活跃边：3
临时边 TTL：1
路由预设：平衡模式
```

不要手填八项权重，第一轮测试先使用“平衡模式”。

## 四、恢复、汇聚与结束

### 7. 恢复边界

- 节点名称：`团队异常恢复边界`
- 节点描述：`当团队成员失败且无法自动替换时，转入兜底说明`
- 恢复模型：DeepSeek
- 通过出口：`pass`
- 恢复出口：`recover`

连线：

```text
智能体团队 → 团队异常恢复边界
pass → 结果汇聚器
recover → 兜底说明 Agent
兜底说明 Agent → 结果汇聚器
```

### 8. 兜底说明 Agent

这是团队外普通 Agent。

- 名称：`兜底说明 Agent`
- 职责描述：`说明哪些资料或资源不可用，并生成可执行的人工补充建议`
- 模型：DeepSeek
- 系统提示词：

```text
团队发生资源或执行失败。请基于已有结果，
说明失败原因、已完成部分、缺少资源以及下一步人工操作建议。
不要虚构不存在的资料。
```

### 9. 结果汇聚器

- 节点名称：`最终方案汇聚`
- 汇聚目标描述：

```text
综合团队成员结果，形成结构完整、无重复、可执行的最终技术方案。
```

- 汇聚模型：DeepSeek
- 汇聚策略：`综合生成`
- 高级字段保持：

```text
成员结果字段：team_results
输出字段：aggregated_result
```

### 10. 目标检查器

- 节点名称：`最终结果检查`
- 检查字段：`input`
- 完成条件：`不为空`
- 完成出口：`complete`
- 继续出口：`continue`

连线：

```text
结果汇聚器 → 最终结果检查
complete → 结束
continue → 补救 Agent
补救 Agent → 结束
```

### 11. 补救 Agent

- 名称：`最终补救 Agent`
- 职责描述：`补全未完成的最终方案`
- 模型：DeepSeek
- 系统提示词：

```text
根据当前已有内容补齐缺失部分，确保最终回答包含：
动态路由、资源指标、Handoff、故障恢复和测试计划。
```

### 12. 结束

保持：

```text
输出字段：input
```

## 五、测试输入

在右上角“测试”中输入：

```text
请完成一个“面向超长程复杂任务的动态异构群体智能架构”小型验证：
先理解赛题资料库中的比赛要求和论文资料，分析动态路由、低熵通信、
时态证据记忆、神经符号与故障恢复四部分应如何实现。

请先由任务接待 Agent 判断任务；如果需要资料证据，必须自主 Handoff 给资料检索 Agent；
检索完成后再自主 Handoff 给方案综合 Agent。最终输出完整架构、关键数据结构、
模块分工、创新点和端到端测试计划。
```

## 六、你应该观察到的正确运行轨迹

正常情况下：

```text
开始
→ 全局任务规划
→ 任务标准化
→ 任务类型识别
→ 复杂任务二次确认
→ 注入团队任务
→ 动态异构研究团队
    → 任务接待与分流 Agent
    → 橙色虚线：自主 Handoff
    → 资料检索 Agent
    → 橙色虚线：自主 Handoff
    → 方案综合 Agent
→ 团队异常恢复边界（pass）
→ 最终方案汇聚
→ 最终结果检查（complete）
→ 结束
```

在“运行观测”中，应至少能看到：

```text
候选成员硬过滤
动态委派
主管已批准智能体自主 Handoff
目标检查
团队结果汇聚
```

点击“查看路由依据”，应能看到每个被选择成员的：

```text
semantic_similarity
prompt_task_match
historical_success
tool_availability
skill_availability
knowledge_availability
normalized_cost
normalized_latency
failure_risk
```

不要把循环、批处理、防漂移检查硬塞进这条测试链路；它们适合做第二组“长任务迭代与代码工程”测试。这个例子先验证动态团队最核心、最有展示价值的一条完整链路。
