### 结果解释

Plain Agent 缺少记忆和上下文治理模块，无法保持目标、约束或历史事实，也不能检测漂移、处理预算压力和从中断恢复。Full-Context Agent 可以保留目标和约束，并以全部上下文获得部分历史事实，但平均使用 864.12 token，超过本实验 320 token 的最大上下文设置，Budget Violation 为 1.0。Memory Only 能以较低 token 获取部分历史事实，但不具备目标账本、漂移检测、预算控制和检查点恢复能力，因此 Final Task Success 仍为 0。

Ours Full 在 Goal Retention、Constraint Compliance、Drift Detected、Pause Correctness 和 Recovery Success 上均达到 1.0，同时没有漂移、重复步骤和预算违规；平均 token 为 143.28，明显低于 Full Context 的 864.12。其 Final Task Success 为 0.83，由于该指标是六项机制条件的合取，17 条未通过均对应 `Memory Use Accuracy=0`，其他关键机制条件已通过。

### Memory Use Accuracy 的评测限制

当前代码使用区分大小写的精确子串规则 `expected_memory in visible_memory` 计算 Memory Use Accuracy。失败样本中存在检索证据语义正确但字符串未严格匹配的情况，例如期望值为 `Photography`，检索记忆中出现 `photography`；也存在数字表达、答案概括或同义表达差异。因此 0.83 不能直接解释为严格意义上的“检索准确率为 83%”或“17 条真实检索失败”。正式报告应将其标注为 exact-substring memory-use proxy，后续若要形成更可靠结论，应增加大小写归一化、规范化字符串匹配或语义 evaluator。

该实验的 Final Task Success 是确定性后端机制条件的合取，不是真实 LLM Agent 的端到端任务成功率。

### 评测器修正记录（保留原结果，不覆盖）

对修正前 Ours Full 的 17 条失败样本进行逐条检查后发现，当前 `Memory Use Accuracy` 使用区分大小写的原始字符子串判断：

```python
example.expected_memory in visible_memory
```

其中 16 条主要来自 `Photography`/`photography` 一类大小写差异。直接做大小写和表面形式归一化后的第一次重跑（v2）得到 Ours Full 97/100，而剩余 3 条暴露了数据构造阶段的另一个字符子串误匹配问题：

- `two` 被匹配到无关文本中的连续字符；
- `Ned` 被匹配到 `signed` 的词尾；
- `a kayak` 被匹配到 `kayaking`。

因此进行了两项统一修正：

1. `Memory Use Accuracy` 改为 token 序列匹配，使用 Unicode NFKC、`casefold()`、标点/空格归一化，并将 `zero` 到 `ten` 的英文数字词统一为阿拉伯数字；
2. LoCoMo 状态任务选择 `memory_fact` 时使用同一套 token 边界规则，避免答案误命中无关单词片段。

新增测试覆盖大小写等价、`two`/`2` 等价、英文标点差异、中文文本、禁止短答案误命中较长单词，以及数据构造必须选择真正包含答案的事实。相关测试结果为 `7 passed`。

第一次规范化重跑 v2 保存在 `runs/experiments/long_task_normalized_v2/`，结果为 Ours Full 97/100。该结果作为定位数据构造问题的中间诊断记录保留，不作为正式主表结果。

## 全套离线验收与实验二前置修正

### Token 统计测试失败记录

按照 `docs/8.29实验3跑起来步骤.md` 的要求执行以下离线检查：

```powershell
python -m compileall engine/experiments examples/experiments
python -m pytest tests/test_experiments.py --basetemp tmp/pytest_experiments -q
```

首次验收结果为：

```text
compileall：通过
pytest：11 passed, 1 failed
```

失败测试为 `tests/test_experiments.py` 中的 `test_memory_control_baselines_report_tokens`。该测试用于验证 Full Context 相对于 No Memory 确实暴露了更多历史上下文，属于实验二长期记忆 runner 的基础对照测试，不是实验一、实验三或实验四的运行失败。

原断言比较的是总 token：

```python
assert full_context.summary()["avg_tokens"] > no_memory.summary()["avg_tokens"]
```

但 `avg_tokens` 同时包含 QA prompt、问题、历史上下文和预测输出。由于两种方法的预测文本长度可能不同，即使 Full Context 的历史上下文更多，其总 token 也不保证在每个极小测试样本上都更高。本次测试中 No Memory 为 18，Full Context 为 16，因此原断言失败。

### 测试指标修正

测试真正需要验证的是“Full Context 暴露的历史上下文 token 多于 No Memory”，因此将断言改为比较专门记录的 `avg_context_tokens`：

```python
assert (
    full_context.summary()["avg_context_tokens"]
    > no_memory.summary()["avg_context_tokens"]
)
```

该修改只修正自动测试所比较的指标，没有修改 `engine/experiments/memory.py` 中的实验计算逻辑，也没有改变实验一、实验三或实验四的已有结果。长期记忆 runner 仍分别保留：

- `context_tokens`：可见/检索历史上下文的 token 估算；
- `qa_input_tokens`：QA 输入 token；
- `qa_output_tokens`：QA 输出 token；
- `tokens`：输入与输出合计 token。
