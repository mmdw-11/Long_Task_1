### QA 指标修正（2026-08-31）

### DeepSeek Thinking 模式兼容修正（2026-08-31）

首次启用语义 Judge 后，No Memory 与 Full Context 的 `qa_judge_tokens` 均有消耗且 API 未抛出异常，但 `qa_judge_response` 为空，导致所有 `qa_acc` 仍为 0。最小接口诊断显示：

```text
finish_reason: length
content: ''
reasoning_content: 'We need to compare reference answer 6 and candidate'
completion_tokens: 10
reasoning_tokens: 10
```

根因是 `deepseek-v4-flash` 默认开启 thinking，而 Judge 原配置的 `max_tokens=10` 全部被内部推理占用，尚未生成最终 `yes/no` 就因长度上限结束。修正方式是在 Judge 请求中显式发送 `thinking.type=disabled`；Judge 只执行二分类，不需要额外思维链。另增加空响应保护：若最终 `content` 仍为空，将写入 `qa_judge_error`，不再无错误地静默记为负例。

该轮空 Judge 响应作为诊断运行保留，不纳入正式实验二对比。修正后最小接口测试返回 `finish_reason=stop`、`content='yes'`、`reasoning_content=None`，服务器离线验收仍为 `15 passed`；有效 Pilot 结果记录在上方“实验二”章节。

### Mem0 DeepSeek JSON 抽取兼容修正（2026-08-31）

Mem0 `infer=True` Pilot 在逐会话抽取记忆时连续出现 `Error parsing extraction response`，继续运行会消耗 API 额度且产生不完整记忆库，因此主动中止并将现场保存为 `mem0_infer_malformed_json_20260831`。该运行不纳入实验结果。

检查服务器实际安装的 `mem0ai==2.0.19` 后确认：其 `DeepSeekConfig` 不提供 `thinking`/`extra_body` 字段，参数过滤层也不会可靠地从项目配置传入该字段；适配器最终只读取 `message.content`。因此不能只在配置字典中增加参数，也不应直接修改 `.venv/site-packages`。

项目侧在创建 Mem0 实例后，对该实例的 OpenAI-compatible `chat.completions.create` 入口增加局部包装，强制每次 Mem0 LLM 请求携带 `extra_body={"thinking":{"type":"disabled"}}`。该修改仅影响本次 Mem0 实例，保留其他请求字段，并在结果 metadata 中记录 `thinking_disabled=true`。新增单元测试验证字段被强制覆盖且其他 `extra_body` 内容不丢失。完整 Pilot 重跑前必须先进行单条记忆的 `infer=True` 写入与检索测试，并确认没有 JSON 解析错误。

修复后先完成一条合成记忆的 `infer=True` 写入与检索：抽取结果正确生成“train 8 dollars / taxi 14 dollars”记忆，BGE/Qdrant 检索分数为 `0.7749`，JSON 解析错误为 0。随后从冻结的 LongMemEval Pilot 中选取 3 个真实会话，长度分别为 8,744、17,423 和 20,874 字符；三次 `ADD` 均产生有效记忆，三次搜索均返回结果，`Error parsing extraction response` 为 0，并正常输出完成标记。由此确认关闭 thinking 的修正对真实长会话生效，可以重新启动原定的 Mem0 `infer=True` Pilot。测试脚本中的旧式顶层 `user_id` 搜索参数曾触发一次 API 用法错误，改为 Mem0 2.0.19 要求的 `filters={"user_id": ...}` 后检索成功；正式 runner 原本已使用正确写法，无需为此修改实验代码。

### Mem0 检索来源追踪修正（2026-08-31）

有效 Mem0 Pilot 中第一题 QA 正确，但旧版 `MRR/Hit@5/Evidence Recall` 仍为 0。原因是 Mem0 返回抽取后的短事实，而 gold evidence 是完整原始会话，直接做字符串包含比较必然漏记抽象式命中。写入 Mem0 时原本已经在 metadata 保存原始会话 `index`，因此修正 runner：QA 仍使用抽取事实作为可见上下文；检索评测则按返回项的 `metadata.index` 回溯同一排名位置上的来源会话，再与 gold session 比较。无有效 index 时才退回抽取文本。该修正不改变 QA 预测、token、耗时或检索排序，只修复 Mem0 的检索指标归因，并新增来源映射单元测试。正式规模运行必须使用修正后的版本；已有 Pilot 的检索指标需通过现有 Qdrant 存储进行无 LLM 的重新搜索后校正。

### Ours benchmark 记忆作用域隔离修正（2026-08-31）

首次 Ours no Judge Pilot 虽成功写入 95 条记忆，但两条 LongMemEval 问题共用 `project_id=longmemeval` 的 PROJECT 层。第二条运行时会读到第一条的历史，运行结束后的回查也会让第一条看到两题混合数据；诊断中每题实际只有 42/53 个会话，却能返回 60 条并出现明显跨主题内容，证明 benchmark 样本隔离不成立。该轮结果不纳入实验二有效对比。

修正后每个问题记录使用独立的 `project_id={source}-{question_id}`，同时保留各自 `task_id`，从存储层阻止跨样本历史污染。新增单元测试验证不同问题的 project scope 必须不同。该改动只影响 benchmark runner 的样本隔离，不改变实际系统中同一项目共享 PROJECT 记忆的产品语义；Ours no Judge 与 Ours Full Pilot 均需在隔离修正后重跑。

### Ours Top-K 冷归档水合修正（2026-08-31）

作用域隔离后，每题检索数量正确恢复为 42/53，但所有返回内容都固定约 1200 字符。原因是 PROJECT 层对超过阈值的会话保存完整 Markdown Raw archive，同时在索引中仅保留 1200 字符摘要；实验 runner 直接把摘要 `item.content` 交给 QA，没有调用存储层已有的 `store.expand(item)`。诊断显示第一题两个 gold 会话按语义已排到第 2、第 1 位，但完整会话分别为 8,744 和 13,434 字符，答案可能位于摘要截断位置之后；第二题同样存在 17k/16k 字符会话被截成 1200 字符的问题。

修正后仍使用摘要向量进行 Top-K 排序，只对最终命中的 Top-K 归档项调用 `store.expand` 恢复完整 Raw 内容，再将其用于 QA 和 evidence evaluation。结果 metadata 记录每条样本实际展开的归档数量，summary 记录 `archive_expand_policy=expand_all_retrieved_top_k`。该逻辑复用现有冷归档接口，符合“摘要索引、命中后按需恢复原文”的系统设计；新增单元测试验证归档命中必须返回完整内容。此前只使用 1200 字符预览的 Ours no Judge 运行无效，需再次重跑。

### Ours Full 更新 Judge 防浪费修正（2026-08-31）

Ours Full 的 `OpenAIMemoryJudge` 同样使用 DeepSeek 严格 JSON 输出，但原实现未关闭默认 thinking，也未限制合理输出长度；JSON 解析失败时仅返回空列表，实验会继续发起后续调用，存在额度浪费风险。修正后更新 Judge 显式发送 `thinking.type=disabled`，输出上限设为 500 tokens，并记录调用次数、JSON 解析错误数与 thinking 状态。实验 runner 在首次解析错误后立即 fail-fast，阻止继续消耗 API；summary 增加 `memory_judge_calls`、`memory_judge_parse_errors`、`memory_judge_thinking_disabled`。新增单元测试验证请求参数、合法 action 解析和计数器。完整 Pilot 前只允许一次最小 Judge 调用验收。

### Mem0 来源审计标签补充（2026-08-31）

正式 Mem0 已在计算检索指标时使用返回事实的 `metadata.index` 回溯来源会话，MRR/Hit/Evidence Recall 因此有效；但 row metadata 未写入 `retrieval_provenance` 审计标签，检查脚本显示 `provenance_rows=0`。修正 runner 为后续运行显式写入 `retrieval_provenance=mem0_metadata_index_to_source_session`。该修改不改变任何指标、排序或预测；现有 N=10 rows 只需无 API 补充标签并重新生成 summary/report，无需重跑 469 次抽取。
