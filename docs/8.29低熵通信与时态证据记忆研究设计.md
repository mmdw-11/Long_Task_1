# 低熵通信与时态证据记忆

## 1. 基线审计

原系统以 `messages` 加 append reducer 形成共享全文历史。节点输出在 graph state 中传播，routing hook 只改变后继节点；它既不决定消息收件人，也不衡量一条消息是否对接收者有贡献。`ContextCompressor` 的字段摘取和字符裁剪适合作为工程保护，但不能声称实现了语义信息瓶颈。Context ledger 已能保存目标、约束、todo、摘要和 raw reference，但 `ContextFact` 仍是文本记录。四级 memory store、SQLite、archive、embedding 与 hybrid retrieval 是本设计复用的持久化底座。

旧 `messages`、state reducer、REST/SSE 事件、数据库和 checkpoint 均保留。结构化通信由 `Orchestrator.set_communication_manager` 显式开启。

## 2. 模块与数据流

```text
agent output
    │ legacy adapter / explicit capsule
    ▼
MessageCapsule ── digest + provenance + state revision
    │
    ├── contribution gate ── prune event
    ▼
field-aware compressor ── optional LLMLingua-2 adapter
    │
    ▼
target mailbox + StateDelta ── graph/SSE events ── recipient context
    │
    ▼
deterministic fact extraction
    │
    ▼
TemporalEvidenceMemoryStore
    ├── evidence/provenance
    ├── fact versions and half-open validity
    ├── conflict sets
    └── time/source/conflict-aware ranked retrieval
```

`MessageCapsule` 把 goal、subtask、claim、evidence、constraint delta、next action、uncertainty、TTL、budget 和 provenance 变为可验证协议。规范化 JSON 的 SHA-256 digest 用于去重、审计与 checkpoint 水位线；压缩产物以 `parent_digest` 连接原消息。每个 agent 只接收 graph 后继或显式收件人的 capsule。

`TemporalEvidenceMemoryStore` 与 `HybridTieredMemoryStore` 共享 SQLite 连接和 embedding model，只增建表，不修改 `memories`。

## 3. 算法

### 3.1 接收者相关的贡献门控

```text
C(m,r) = w_t R_task + w_i I_gain + w_e Q_evidence
       + w_r F_role + w_f Freshness
       - w_d Redundancy - w_b BudgetPressure
```

默认权重位于 `configs/communication_policy.yaml`。Redundancy 是 capsule 与接收者 mailbox 历史的 token Jaccard 最大值。达到 redundancy threshold 的消息直接裁剪。constraint delta 和显式 conflict 是 protected semantics。

```text
for recipient in explicit_recipients or graph_successors:
    if expired(capsule): PRUNE(expired)
    score, components = contribution(capsule, recipient)
    if protected(capsule) or (score >= threshold and not redundant):
        DELIVER(recipient, compress_under_budget(capsule), score_breakdown)
    else:
        PRUNE(low_contribution/redundant)
```

### 3.2 增量状态通信

```text
changed = {k: S[r][k] | S[r][k] != S[r-1][k]}
removed = keys(S[r-1]) - keys(S[r])
delta   = (base_revision=r-1, revision=r, changed, removed)
```

内部 `__*` 字段与原始 `messages` 不进入差分。checkpoint 保存 revision 与各接收者已见 digest；resume 时恢复水位线。

### 3.3 事实更新、冲突与版本

事实使用 `(subject, predicate, object, [valid_from, valid_to))`：

```text
if same_object and validity_overlap:
    merge evidence; confidence = 1-(1-c_old)(1-c_new)
elif different_object and replace:
    old.status = superseded; old.valid_to = new.valid_from
    new.supersedes_id = old.id; new.version = old.version + 1
elif different_object and validity_overlap:
    assign conflict_set_id; mark every member disputed
else:
    add active fact
```

失效采用非破坏性更新并保留 `fact_versions` 快照。显式 `as_of=t` 使用半开区间判定。

### 3.4 时间与证据感知检索

```text
Score(f,q,t) = α dense + β sparse + γ validity(t)
             + δ source_reliability + ε evidence_support
             + ζ task_agent_scope + η recency
             - κ conflict_indicator
```

API 返回 `FactSearchResult.score_breakdown`。默认排除过期、失效、被替代和 disputed 事实；`include_history`、`include_conflicts`、`as_of` 可改变视图。

## 4. 实验设计

```powershell
python examples/experiments/run_communication_memory_experiment.py
```

固定 seed 为 42，产物写到 `runs/experiments/communication_memory/<method>/`。通信方法为 `free_text_append`、`structured_no_gate`、`structured_gate_compress`；指标包括 tokens、compression ratio、delivered edges、pruned、critical-field fidelity 和 latency。

记忆方法为普通 tiered baseline 与 temporal evidence；指标包括 temporal accuracy、conflict accuracy、stale-fact rate 和 latency。内置 JSONL 覆盖知识更新与冲突；正式实验继续使用 LongMemEval 的 knowledge update、temporal reasoning、abstention 和 LoCoMo temporal 类别。

离线样本验证算法行为与可复现性，不替代官方 benchmark 的生成式 QA 结果。缺少模型凭据时，模型对照必须标记 skipped。

## 5. 论文贡献与工程替代

可作为论文方法：接收者条件化的可解释贡献门控；带 digest lineage 的结构化协议；graph successor 定向通信和 revision state delta；证据与来源绑定的半开区间事实；显式 conflict set 与非破坏性版本演化；具有 score decomposition 的联合检索。

当前工程替代：默认 redundancy 是 token Jaccard，而非训练的 AgentPrune mask；默认摘要器是字段规则；capsule 到 SPO 的确定性抽取以 `claims` 和 constraint predicate 为主；尚无 HippoRAG 2 的 Personalized PageRank；来源可靠度是配置先验。这些组件都有 adapter 边界，可逐项替换和消融。

## 6. 参考实现与接入判断

- AgentPrune：借时空图和边剪枝思想；训练代码不直接接入。
- DyLAN：借 agent importance、动态选择和 early stop；不引入任务框架。
- GPTSwarm：借可优化 graph edge；保留本项目 graph engine。
- TalkHier：结构化主管/成员协议可低成本重写。
- LongMemEval / V2：数据和 harness 可接；超大 V2 haystack 需额外算力。
- A-Mem：动态 note linking/evolution 借思想。
- HippoRAG 2：后续可选 graph retrieval backend。
- mem0：已有真实可选 baseline，graph extras 可进一步接入。
- LLMLingua-2：通过 `LLMLinguaCapsuleCompressor` 可选接入。

## 7. 风险与下一步

- 模型只能建议实体归一化，不能修改 provenance 或绕过验证。
- SQLite WAL 支持当前并发，但跨进程 upsert 应使用单写者或 PostgreSQL。
- checkpoint 当前持久化水位线而非全部未消费 envelope；跨进程恢复 mailbox 时应将 envelope 写入 TASK scope。
- 后续优先实现学习式 edge mask、来源信誉校准、图关联扩展和 LongMemEval-V2 accuracy-latency frontier。
