下面给你一条只测试“动态逻辑”的完整流程，不放条件判断、脚本、循环、批处理等静态逻辑。

## 一、总图

```text
开始
  ↓
任务规划器
  ↓
智能体团队
  ├─ 接待分流 Agent
  ├─ 资料检索 Agent
  └─ 方案综合 Agent
  ↓
故障恢复边界
  ├─ pass → 结果汇聚器
  └─ recover → 兜底 Agent → 结果汇聚器
                                  ↓
                             目标检查器
                              ├─ complete → 结束
                              └─ continue → 补救 Agent → 结束
```

团队内部不要画静态连线。运行时会自动显示：

```text
接待分流 Agent ──自主 Handoff──→ 资料检索 Agent
资料检索 Agent ──自主 Handoff──→ 方案综合 Agent
```

## 三、任务规划器配置

- 节点名称：`动态任务规划`
- 节点描述：

```text
把复杂任务拆解为可追踪子任务，并为后续团队路由提供上下文。
```

- 规划模型：选择 `DeepSeek`
- 规划方式：`按目标自适应拆分`

高级配置保持：

```text
输入字段：input
计划输出字段：task_plan
最大子任务数：8
```

## 四、智能体团队配置

### 团队基础配置

- 名称：`动态研究协作团队`
- 描述：

```text
根据当前任务动态选择成员，并允许成员在能力不足时自主 Handoff。
```

- 输入字段：`input`
- 输出字段：`team_result`

### 协作方式

```text
首轮协作：仅选择一位成员
本轮选择数：1
最大并发：1
允许成员发起自主 Handoff：开启
最大 Handoff 次数：2
```

### 团队结果汇聚

```text
团队内结果汇聚：结构化拼接
```

### 故障恢复

```text
成员失败时自动选择备用成员：开启
```

高级配置：

```text
拓扑策略：任务自适应稀疏
最大活跃边：3
临时边 TTL：1
路由预设：平衡模式
```

## 五、团队成员配置

### 1. 接待分流 Agent

拖入智能体团队内部。

基础配置：

- 名称：`接待分流 Agent`
- 描述：

```text
负责理解用户需求并判断下一步需要资料检索还是方案设计。
```

- 模型：`DeepSeek`

系统提示词：

```text
你是任务接待与分流专家。

你的任务是先理解用户目标，不要直接完成复杂研究。
如果任务需要查阅资料、论文、比赛文档或知识证据，
必须把任务转交给资料检索 Agent。

请在回答最后单独输出一行 JSON，不要使用 Markdown：

{
  "status": "needs_handoff",
  "remaining_task": "需要资料检索 Agent 完成的下一步任务",
  "required_capabilities": ["资料检索", "论文证据"],
  "reason": "当前任务需要外部资料和证据",
  "context_summary": "已经理解的用户目标和任务背景"
}
```

团队成员配置：

```text
允许动态调用：开启
优先级：5
能力标签：需求理解、任务分流、任务拆解、Handoff
```

### 2. 资料检索 Agent

拖入智能体团队内部。

基础配置：

- 名称：`资料检索 Agent`
- 描述：

```text
负责检索赛题资料、论文证据和相关技术实现，并整理可追溯的研究结论。
```

- 模型：`DeepSeek`

系统提示词：

```text
你是资料检索专家。

请根据接收到的任务，整理相关赛题资料、论文观点、
技术实现和可采用的开源方案。

完成资料检索后，不要直接生成最终架构方案，
而是把下一步任务转交给方案综合 Agent。

请在回答最后单独输出一行 JSON：

{
  "status": "needs_handoff",
  "remaining_task": "基于检索结果形成完整的动态异构群体智能架构方案",
  "required_capabilities": ["架构设计", "方案综合"],
  "reason": "资料检索已完成，需要系统架构整合",
  "context_summary": "检索到的关键事实、技术和证据摘要"
}
```

团队成员配置：

```text
允许动态调用：开启
优先级：1
能力标签：资料检索、论文证据、赛题分析、技术调研
```

如果你已经有知识库或 Skill，可以额外挂载：

```text
知识库：赛题与论文资料库
Skill：学术证据检索规范
```

但为了先验证动态逻辑，即使不挂载也可以运行。

### 3. 方案综合 Agent

拖入智能体团队内部。

基础配置：

- 名称：`方案综合 Agent`
- 描述：

```text
根据用户目标和资料检索结果，输出动态异构群体智能架构和验证计划。
```

- 模型：`DeepSeek`

系统提示词：

```text
你是系统架构与方案综合专家。

请基于用户目标和前序资料检索结果，
输出最终的动态异构群体智能架构方案。

必须包含：

1. 动态路由指标；
2. Agent 自主 Handoff 机制；
3. 团队成员选择方法；
4. 工具、Skill、知识库可用性判断；
5. 故障恢复与备用 Agent；
6. 低熵通信；
7. 时态证据记忆；
8. 神经符号约束；
9. 端到端测试方案。

当前任务完成后直接输出最终结果，不再发起 Handoff。
```

团队成员配置：

```text
允许动态调用：开启
优先级：0
能力标签：系统架构、方案综合、动态编排、测试设计、故障恢复
```

## 六、故障恢复边界配置

- 节点名称：`团队故障恢复边界`
- 节点描述：

```text
当团队成员执行失败且无法自动替换时，进入兜底处理。
```

- 恢复模型：选择 `DeepSeek`
- 通过出口：`pass`
- 恢复出口：`recover`
- 报告输出字段：`recovery_report`

连线：

```text
智能体团队 → 故障恢复边界
pass → 结果汇聚器
recover → 兜底 Agent
```

注意：故障恢复边界不是放在团队前面，而是包住团队的“成功出口”和“最终失败出口”。

## 七、兜底 Agent 配置

- 名称：`团队失败兜底 Agent`
- 描述：

```text
解释团队失败原因，并给出当前已完成内容和人工补救建议。
```

- 模型：`DeepSeek`

系统提示词：

```text
团队执行过程中出现失败。

请说明：
1. 哪个成员失败；
2. 失败原因；
3. 哪些任务已经完成；
4. 哪些信息仍然缺失；
5. 用户下一步应该如何补充或处理。

不要虚构不存在的资料。
```

连线：

```text
兜底 Agent → 结果汇聚器
```

## 八、结果汇聚器配置

- 节点名称：`最终结果汇聚`
- 节点描述：

```text
整合团队成员结果和故障恢复信息，形成一个统一最终答案。
```

- 汇聚模型：选择 `DeepSeek`
- 汇聚策略：`综合生成`

高级配置：

```text
成员结果字段：team_results
输出字段：aggregated_result
```

连线：

```text
结果汇聚器 → 目标检查器
```

## 九、目标检查器配置

目标检查器不需要选择模型。

配置：

```text
节点名称：最终目标检查
检查字段：input
完成条件：不为空
完成出口：complete
继续出口：continue
```

连线：

```text
complete → 结束
continue → 补救 Agent
```

## 十、补救 Agent 配置

- 名称：`最终补救 Agent`
- 描述：

```text
补充最终答案中缺失的架构、指标或测试内容。
```

- 模型：`DeepSeek`

系统提示词：

```text
请检查当前最终结果是否包含动态路由、
Handoff、故障恢复、资源可用性和测试方案。

如果存在缺失，请补齐后直接输出最终结果。
```

连线：

```text
补救 Agent → 结束
```

## 十一、节点连线汇总

严格按照下面连接：

```text
开始
  → 动态任务规划
  → 动态研究协作团队
  → 团队故障恢复边界
```

恢复边界：

```text
pass
  → 最终结果汇聚

recover
  → 团队失败兜底 Agent
  → 最终结果汇聚
```

后续：

```text
最终结果汇聚
  → 最终目标检查
```

目标检查：

```text
complete
  → 结束

continue
  → 最终补救 Agent
  → 结束
```

团队内部：

```text
接待分流 Agent
资料检索 Agent
方案综合 Agent
```

三者只拖入团队，不连接固定边。

## 十二、测试总任务

在测试窗口输入：

```text
请完成一个动态异构群体智能架构研究任务。

请先理解“面向超长程复杂任务的动态异构群体智能架构与深度协同推理技术”这一比赛方向，
分析动态路由、低熵通信、时态证据记忆、神经符号推理和故障恢复的实现方案。

本次任务必须按照以下协作方式执行：

1. 先由接待分流 Agent 理解任务；
2. 接待分流 Agent 不要直接完成研究，必须自主 Handoff 给资料检索 Agent；
3. 资料检索 Agent 整理论文、赛题和技术证据；
4. 资料检索 Agent 完成检索后，必须自主 Handoff 给方案综合 Agent；
5. 方案综合 Agent 输出最终完整方案；
6. 最终结果必须包含实现模块、数据结构、路由指标、故障恢复机制和端到端测试计划。

请在最终回答中说明本次运行中每次 Agent 选择和 Handoff 的原因。
```

## 十三、正确的运行结果

运行观测中应看到：

```text
动态任务规划
  ↓
动态团队评估候选成员
  ↓
选择接待分流 Agent
  ↓
接待分流 Agent 请求 Handoff
  ↓
主管选择资料检索 Agent
  ↓
资料检索 Agent 请求 Handoff
  ↓
主管选择方案综合 Agent
  ↓
团队目标检查通过
  ↓
团队故障恢复边界 pass
  ↓
最终结果汇聚
  ↓
目标检查 complete
  ↓
结束
```

画布运行时颜色：

```text
紫色边：动态委派
橙色虚线：自主 Handoff
红色虚线：故障替换
```

如果 DeepSeek 没有输出 Handoff JSON，说明模型没有遵守协议。此时检查：

- Agent 系统提示词是否完整；
- 团队“允许成员发起自主 Handoff”是否开启；
- `最大 Handoff 次数`是否大于 0；
- 接待 Agent 和资料检索 Agent 的能力描述是否填写；
- 运行观测中是否出现 `goal_checked` 和 `handoff_selected` 事件。
