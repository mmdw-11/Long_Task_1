

最终实验主线是：

> 证明你的系统相比普通 Agent，在长任务中具备更强的 **编排稳定性、长期记忆能力、状态保持能力、技能复用能力**。

端-边-云路由可以作为补充实验或附录，不建议放进 2 天主实验里硬跑。

**最终保留的 4 组实验**

1. 多 Agent 编排稳定性实验
2. 长期记忆主实验
3. 长期记忆 + 上下文治理联合实验
4. 技能闭环实验，小规模保留

其中第 2、3、4 是重点，第 1 是基础

**实验一：多 Agent 编排稳定性实验**

目的：先证明你的后端图执行能力稳定，这是后面所有模块实验的基础。

数据集：使用现有自建 workflow 数据集，跑 **300 条**。

覆盖 5 类结构：

| 类型 | 数量 |
| --- | ---: |
| 顺序执行 | 60 |
| 扇出扇入 | 60 |
| 条件分支 | 60 |
| 父子 Agent | 60 |
| 循环控制 | 60 |

方法只保留：

| 方法 | 说明 |
| --- | --- |
| Ours Orchestrator | 当前 `Orchestrator + StateGraph` |

这里不用再加 LangGraph 对照，2 天时间不值得。这个实验的作用是证明系统工程基础可靠。

指标：

- Sequence Accuracy
- Branch Accuracy
- Loop Stop Success
- Trace Completeness
- Avg Execution Time

预期结论：

> 系统能稳定支持顺序、分支、循环、父子 Agent 和扇出扇入结构，为后续长期记忆和技能注入实验提供可靠执行基础。

**实验二：长期记忆主实验**

这是最重要的一组。

目的：证明你的记忆模块在公开长记忆任务上，能以更少上下文成本完成有效记忆检索和问答。

数据集：

| 数据集 | 数量 | 用途 |
| --- | ---: | --- |
| LongMemEval | 100 条 | 主实验 |
| LoCoMo | 50 条 | 补充验证 |

为什么这个数量合适：

- 2 天内能跑完；
- 比 2 条 sample 正式得多；
- LongMemEval 100 条足够做主表；
- LoCoMo 50 条证明不是只适合单一数据集；
- 如果 mem0 很慢，可以先对 mem0 只跑 LongMemEval 50 条，并在表里说明。

方法保留 5 个：

| 方法 | 说明 |
| --- | --- |
| No Memory | 不使用历史记忆 |
| Full-Context | 全量历史直接拼进上下文 |
| mem0 | 外部记忆框架 baseline |
| Ours no Judge | 关闭 LLM 记忆更新判断 |
| Ours Full | 完整记忆模块 |

指标：

| 指标 | 含义 |
| --- | --- |
| Hit@5 | 正确记忆是否进入 Top-5 |
| MRR | 正确记忆排序质量 |
| QA Acc | 最终回答是否正确 |
| Answer F1 | 生成答案与标准答案的重叠程度 |
| Avg Tokens | 平均上下文 token |
| Avg Time | 平均耗时 |

这里一定要新增回答成功率。也就是：

```text
检索出 top-k memories
→ question + retrieved memories
→ 固定 QA solver 生成答案
→ 和 gold answer 比较
```

QA solver 建议：

- 用 DeepSeek / 你当前项目默认云端模型；
- temperature=0；
- 所有方法共用同一个 solver；
- prompt 固定。

主表：

| Method | Dataset | N | Hit@5 | MRR | QA Acc | Answer F1 | Avg Tokens | Avg Time |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| No Memory | LongMemEval | 100 |  |  |  |  |  |  |
| Full-Context | LongMemEval | 100 |  |  |  |  |  |  |
| mem0 | LongMemEval | 50/100 |  |  |  |  |  |  |
| Ours no Judge | LongMemEval | 100 |  |  |  |  |  |  |
| Ours Full | LongMemEval | 100 |  |  |  |  |  |  |
| Ours Full | LoCoMo | 50 |  |  |  |  |  |  |

预期结论：

> Ours Full 在 QA Acc 和 MRR 上接近或优于 mem0 / Ours no Judge，同时相比 Full-Context 显著降低 token 成本。



**实验三：长期记忆 + 上下文治理联合实验**

这是体现你系统独特设计的核心实验。它证明你的长期记忆不是孤立模块，而是和 ContextLedger、DriftDetector、BudgetController 一起支撑长任务。

目的：

> 证明在长任务中，Ours Full 能同时保持目标、遵守约束、正确使用记忆、控制漂移和预算。

数据集：自建 **100 条从LoCoMo中抽取出来的样本**。


每条样本包含：

- 原始目标
- 2 条硬约束
- 1 条必须使用的历史记忆
- 1 条错误干扰事实
- 1 个中途新增约束
- 1 个重复/漂移风险
- 1 个预算压力片段

方法保留 4 个：

| 方法 | 说明 |
| --- | --- |
| Plain Agent | 无记忆、无上下文治理 |
| Full-Context Agent | 全量拼接历史 |
| Memory Only | 只用长期记忆 |
| Ours Full | 记忆 + Ledger + Drift + Budget + Checkpoint |

不建议保留 `Context Only`，因为你的重点是长期记忆与上下文治理联合，不需要把表做太大。

指标：

| 指标 | 含义 |
| --- | --- |
| Task Success | 最终任务是否成功 |
| Goal Retention | 是否保持原始目标 |
| Constraint Compliance | 是否遵守硬约束 |
| Memory Use Accuracy | 是否正确使用历史记忆 |
| Drift Rate | 是否发生漂移 |
| Budget Violation | 是否超预算继续执行 |
| Recovery Success | 中断恢复是否成功 |
| Avg Tokens | 平均上下文成本 |

主表：

| Method | N | Task Success | Goal Retention | Constraint | Memory Acc | Drift Rate | Budget Violation | Avg Tokens |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Plain Agent | 40 |  |  |  |  |  |  |  |
| Full-Context | 40 |  |  |  |  |  |  |  |
| Memory Only | 40 |  |  |  |  |  |  |  |
| Ours Full | 40 |  |  |  |  |  |  |  |

预期结论：

> Memory Only 能提高记忆使用，但不能解决目标漂移和预算问题；Full-Context token 高且容易受干扰；Ours Full 同时提升任务成功率、约束遵守率和记忆使用准确率，并降低漂移和预算违规。

**实验四：技能闭环小规模实验**

这个实验保留，但不要做大。它是你“自演化 Agent”特色的证据。

目的：证明系统能从成功轨迹生成可复用技能，并在后续任务中命中。

数据集：自建 **30 条重复任务样本**，分 3 类，每类 10 条：

| 任务类型 | 数量 |
| --- | ---: |
| 邮件处理 | 10 |
| 日历安排 | 10 |
| 旅行规划/报告生成 | 10 |

方法保留 3 个：

| 方法 | 说明 |
| --- | --- |
| No Skill | 不注入技能 |
| Manual Skill | 人工写固定技能 |
| Ours Skill Loop | 候选生成 → 验证 → 发布 → 检索注入 |

指标：

- Skill Generation Success
- Validation Pass Rate
- Retrieval Hit Rate
- Step Coverage
- Task Success
- Avg Tokens

主表：

| Method | N | Task Success | Step Coverage | Retrieval Hit | Avg Tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| No Skill | 30 |  |  |  |  |
| Manual Skill | 30 |  |  |  |  |
| Ours Skill Loop | 30 |  |  |  |  |

预期结论：

> 自动技能闭环能达到接近手写技能的覆盖率，并优于无技能设置，说明系统具备从历史运行中沉淀可复用过程知识的能力。
