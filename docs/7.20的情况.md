## 一、背景
当前要解决的问题是：同一套 AI 服务里同时存在便宜的小模型和昂贵但能力更强的大模型，系统需要先判断“这个请求应该走小模型还是大模型”。

典型目标：
- 简单任务：总结、列待办、创建日程、短文本处理，优先走小模型
- 复杂任务：架构分析、复杂代码、长文档推理、合同风险、隐私审查、多模态理解，优先走大模型

这件事本质上就是一个二分类路由问题：
- `0` = 走小模型
- `1` = 走大模型

## 五、结果解读
### 1. keyword_rule
当前这批数据上，关键词规则依然很强。

特点：
- `accuracy` 很高
- `f1` 很高
- 速度最快
- 几乎没有成本

说明：
- 当前数据集仍带有比较明显的规则特征
- 所以传统规则在这批样本上仍然占优

### 2. nb_router
轻量 NB 已经能跑通，但效果明显弱于规则基线。

特点：
- 召回仍高
- 精确率偏低
- 整体 `f1` 较差

说明：
- 它能作为低成本学习基线
- 但目前不适合作为最终最佳方案

### 3. bert_full / bert_lora
这两个高级模型已经真实训练跑通，但当前结果并不好。

特点：
- `accuracy` 不低
- 但 `precision / recall / f1` 全部接近 0

说明：
- 不是代码失败
- 是当前训练数据分布偏斜，正类样本太少
- 模型学成了偏向预测小模型类

结论：
- 现在不是模型框架不行
- 而是数据集类别不平衡，导致深度模型没学到有效决策边界

### 4. bge_m3
`BGE-M3` 当前是高级方案里表现最好的一个。

特点：
- `accuracy` 接近 `keyword_rule`
- `precision` 达到 `1.0`
- `f1` 达到 `0.8571`
- 延迟比规则和 NB 高，但仍可接受

说明：
- 在当前这批数据上，`BGE-M3 embedding + 轻量分类器` 是最有潜力的学习式方案
- 它已经具备继续优化和写实验结果的价值

## 八、当前最大问题

### 数据集类别分布不平衡
目前扩展数据集里：
- 走小模型样本明显更多
- 走大模型正例偏少

直接后果：
- `bert_full`
- `bert_lora`

这两个深度模型虽然训练成功，但学出来明显偏向负类，导致 `f1` 很差。

这也是为什么：
- `BGE-M3` 还能维持不错表现
- `BERT` 系列反而没有达到预期

---

## 九、下一步最合理的工作
如果继续往前推进，最合理的方向不是再加更多模型，而是先做数据再平衡。

建议顺序：
1. 人工或半自动补更多“大模型正类”样本
2. 保证 `0/1` 类别更平衡
3. 重新训练：
   - `bert_full`
   - `bert_lora`
   - `bge_m3`
4. 重新生成最终实验表

这样下一轮结果才有统计意义。
