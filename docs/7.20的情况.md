## 一、背景
当前要解决的问题是：同一套 AI 服务里同时存在便宜的小模型和昂贵但能力更强的大模型，系统需要先判断“这个请求应该走小模型还是大模型”。

典型目标：
- 简单任务：总结、列待办、创建日程、短文本处理，优先走小模型
- 复杂任务：架构分析、复杂代码、长文档推理、合同风险、隐私审查、多模态理解，优先走大模型

这件事本质上就是一个二分类路由问题：
- `0` = 走小模型
- `1` = 走大模型

## 五、结果解读
### 1. keyword_rule
当前这批数据上，关键词规则依然很强。

特点：
- `accuracy` 很高
- `f1` 很高
- 速度最快
- 几乎没有成本

说明：
- 当前数据集仍带有比较明显的规则特征
- 所以传统规则在这批样本上仍然占优

### 2. nb_router
轻量 NB 已经能跑通，但效果明显弱于规则基线。

特点：
- 召回仍高
- 精确率偏低
- 整体 `f1` 较差

说明：
- 它能作为低成本学习基线
- 但目前不适合作为最终最佳方案

### 3. bert_full / bert_lora
这两个高级模型已经真实训练跑通，但当前结果并不好。

特点：
- `accuracy` 不低
- 但 `precision / recall / f1` 全部接近 0

说明：
- 不是代码失败
- 是当前训练数据分布偏斜，正类样本太少
- 模型学成了偏向预测小模型类

结论：
- 现在不是模型框架不行
- 而是数据集类别不平衡，导致深度模型没学到有效决策边界

### 4. bge_m3
`BGE-M3` 当前是高级方案里表现最好的一个。

特点：
- `accuracy` 接近 `keyword_rule`
- `precision` 达到 `1.0`
- `f1` 达到 `0.8571`
- 延迟比规则和 NB 高，但仍可接受

说明：
- 在当前这批数据上，`BGE-M3 embedding + 轻量分类器` 是最有潜力的学习式方案
- 它已经具备继续优化和写实验结果的价值

## 七、 二轮数据集再平衡

一轮实验存在明显类别不平衡：

- 负类更多
- 正类较少
- BERT 类模型容易塌成只预测一边

因此做了二轮再平衡(long_task_1\examples\router_learning\rebalance_dataset.py)，产物为：

- 数据集：`long_task_1/runs/router_learning/balanced_dataset.jsonl`
- 标签统计：`40` 个小模型样本，`40` 个大模型样本

这一步的作用，是让后续 BERT / BGE-M3 的结果更能真实反映路由能力，而不是被类别分布误导。

### 二轮实验结果

最终对比表在：

- `long_task_1/runs/router_learning/balanced_experiment_table_final.md`

关键结果如下：

| method | accuracy | precision | recall | f1 | 说明 |
| --- | --- | --- | --- | --- | --- |
| keyword_rule | 0.4875 | 0.4545 | 0.1250 | 0.1961 | 关键词/规则基线 |
| nb_router | 0.6625 | 0.7097 | 0.5500 | 0.6197 | 轻量 n-gram + 朴素贝叶斯 |
| bert_full | 0.6250 | 0.5893 | 0.8250 | 0.6875 | `bert-base-chinese` 全参数微调 |
| bert_lora | 0.5000 | 0.5000 | 1.0000 | 0.6667 | `bert-base-chinese` LoRA |
| bge_m3 | 0.6750 | 0.6667 | 0.7000 | 0.6829 | `BGE-M3` embedding + 分类器 |

### 为什么默认先切到 bge_m3

虽然二轮里 `bert_full` 的 F1 最高，为 `0.6875`，但当前默认先切到 `bge_m3`，原因是：

- `bge_m3` 的综合指标非常接近，F1 为 `0.6829`
- `bge_m3` 的 accuracy 反而最高，为 `0.6750`
- 训练和部署链路更稳，适合作为第一版线上默认切换
- 后续如果继续扩充数据集，`bert_full` 可以再作为“指标优先版本”继续比较

所以当前策略是：

- 生产默认：`bge_m3`
- 备选高 F1 路由器：`bert_full`
- 最轻量保底：`nb`
