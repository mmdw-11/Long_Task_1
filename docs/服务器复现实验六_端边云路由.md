# 服务器复现实验六：端—边—云 AUTO 路由

本文用于让另一位同学在一台服务器上复现“Strict-AUTO 对比纯云端”的 100 条 C-Eval 实验。项目代码、数据集和已训练 BGE-M3 路由分类器随 Git 提交；模型权重和 API 密钥不进入 Git，必须按本文准备。

## 1. 实验做什么

- 数据集：`data/processed/RouteCostBench-100.jsonl`，100 条 C-Eval 验证集选择题。
- 对照组：100 条任务全部调用云端 `deepseek-v4-flash`。
- 实验组：BGE-M3 + MLP 已训练路由器为每条任务选择端、边或云；严格模式下不允许回退到其它层。
- 端侧：`qwen2.5:0.5b-instruct`；边侧：`qwen2.5:3b-instruct`；均由 Ollama 提供服务。
- 输出：共 200 条记录（100 条对照 + 100 条 AUTO），统计准确率、云 API 成本、延迟、路由命中率和回退次数。

## 2. 从 Git 获得的内容

克隆仓库后，以下文件已经具备，无需训练：

- `runs/router_learning/final_bge_m3_mlp/classifier.pkl`：已训练 BGE-M3 路由分类器。
- `runs/router_learning/final_bge_m3_mlp/summary.json`：分类器训练配置与指标。
- `data/processed/RouteCostBench-100.jsonl`：固定的 100 条实验数据。
- `ollama_modelfiles/`：两个 Qwen GGUF 的 Ollama 注册模板。
- `examples/experiments/run_routing_experiment.py` 与 `engine/experiments/routing.py`：实验启动和记录逻辑。

不要重新训练路由器。服务器只需使用 Git 中的 `classifier.pkl`，并提供与之配套的 BGE-M3 基座模型。

## 3. Git 不包含、但服务器必须准备的资产

| 资产 | 用途 | 获取方式 |
| --- | --- | --- |
| BAAI/bge-m3 模型目录 | 将任务编码后交给路由分类器 | 从 Hugging Face 下载，或从实验机复制已缓存模型目录 |
| `qwen2.5-0.5b-instruct-q4_k_m.gguf` | 端侧本地模型 | 从实验机复制或按同一量化版本获取 |
| `qwen2.5-3b-instruct-q4_k_m.gguf` | 边侧本地模型 | 从实验机复制或按同一量化版本获取 |
| DeepSeek API Key | 纯云端基线和 AUTO 的云端任务 | 在服务器本地 `.env` 中填写；禁止提交 |

建议服务器目录结构：

```text
/opt/long_task_1/
  long_task_1/                   # Git 仓库根目录
  models/
    bge-m3/                       # 含 config.json 与 model.safetensors/pytorch_model.bin
    qwen2.5-0.5b-instruct-q4_k_m.gguf
    qwen2.5-3b-instruct-q4_k_m.gguf
```

## 4. 创建环境

以下命令以 Linux + Conda 为例：

```bash
git clone <仓库地址> /opt/long_task_1/long_task_1
cd /opt/long_task_1/long_task_1
conda create -n Lang_Task python=3.11 -y
conda activate Lang_Task
pip install -r requirements.txt
```

验证已训练路由器已经随仓库到位：

```bash
test -f runs/router_learning/final_bge_m3_mlp/classifier.pkl && echo 'router ready'
wc -l data/processed/RouteCostBench-100.jsonl
```

第二条应输出 `100`。

## 5. 启动本地端侧、边侧模型

安装并启动 Ollama 后，将两个 GGUF 文件放到同一临时目录，并把对应 `Modelfile` 一并拷入该目录。因为模板使用相对路径，必须在 GGUF 所在目录执行：

```bash
cd /opt/long_task_1/models
cp /opt/long_task_1/long_task_1/ollama_modelfiles/Modelfile-qwen2.5-0.5b-instruct .
cp /opt/long_task_1/long_task_1/ollama_modelfiles/Modelfile-qwen2.5-3b-instruct .
ollama create qwen2.5:0.5b-instruct -f Modelfile-qwen2.5-0.5b-instruct
ollama create qwen2.5:3b-instruct -f Modelfile-qwen2.5-3b-instruct
ollama list
```

`ollama list` 必须显示两个名称。若服务器上的 Ollama 未自动运行，在另一个终端执行 `ollama serve`。

## 6. 配置 .env

复制模板并按服务器实际路径填写：

```bash
cp .env.example .env
```

`.env` 至少应包含：

```dotenv
OPENAI_API_KEY=<你的 DeepSeek API Key>
OPENAI_BASE_URL=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-v4-flash

DEVICE_BASE_URL=http://127.0.0.1:11434/v1
DEVICE_ENDPOINT=http://127.0.0.1:11434/v1
DEVICE_MODEL=qwen2.5:0.5b-instruct

EDGE_MODEL=qwen2.5:3b-instruct
EDGE_OLLAMA_BASE_URL=http://127.0.0.1:11434/v1

ROUTER_MODEL_BACKEND=bge_m3
ROUTER_MODEL_PATH=/opt/long_task_1/long_task_1/runs/router_learning/final_bge_m3_mlp
BGE_M3_MODEL_PATH=/opt/long_task_1/models/bge-m3
```

不能将 `.env` 提交到 Git。

## 7. 运行前检查

先确认 Ollama 的两个模型均能响应：

```bash
curl http://127.0.0.1:11434/v1/models
```

再确认 Python 能加载 BGE-M3 路由器：

```bash
python -c "from engine.modules.scheduling.production import load_production_gate; assert load_production_gate(strict=True); print('BGE router ready')"
```

若此步骤报 BGE 模型路径错误，检查 `BGE_M3_MODEL_PATH` 是否直接指向包含 `config.json` 和 `model.safetensors`（或 `pytorch_model.bin`）的目录。

## 8. 启动正式实验

在仓库根目录、已激活 `Lang_Task` 环境和 Ollama 服务运行后执行：

```bash
python examples/experiments/run_routing_experiment.py \
  --dataset data/processed/RouteCostBench-100.jsonl \
  --output-dir runs/experiments/routing/route-cost-100 \
  --pricing configs/routing_pricing_deepseek_v4_flash.json \
  --env-routing
```

如需后台运行：

```bash
mkdir -p runs/experiments/routing
nohup python examples/experiments/run_routing_experiment.py \
  --dataset data/processed/RouteCostBench-100.jsonl \
  --output-dir runs/experiments/routing/route-cost-100 \
  --pricing configs/routing_pricing_deepseek_v4_flash.json \
  --env-routing > runs/experiments/routing/route-cost-100.log 2>&1 &
```

## 9. 查看进度和验收

运行中：

```bash
tail -f runs/experiments/routing/route-cost-100.log
wc -l runs/experiments/routing/route-cost-100/rows.jsonl
```

日志中的 `progress` 到达 200，且 `rows.jsonl` 为 200 行时完成。最终读取：

- `runs/experiments/routing/route-cost-100/report.md`：汇总报告。
- `runs/experiments/routing/route-cost-100/summary.json`：机器可读指标。
- `runs/experiments/routing/route-cost-100/rows.jsonl`：逐题结果。
- `runs/experiments/routing/route-cost-100/attempts.jsonl`：逐次模型调用记录。

验收条件：

```text
total_rows = 200
all_cloud.n = 100
strict_auto.n = 100
strict_route_match_rate = 1.0
strict_auto 中 fallback = false
attempts.jsonl 中没有 success = false 的调用
```

完成后请保存输出目录，作为本次实验的可审计结果；不要覆盖已有正式结果。
