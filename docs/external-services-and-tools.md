# 外部服务、数据库与工具执行审计

## 当前已经接入

- 云模型：使用 OpenAI-compatible SDK，当前配置指向 DeepSeek API。
- 设备模型：`127.0.0.1:11434/v1`，当前 Ollama 端口正在监听。
- 边缘推理：配置为 `127.0.0.1:8001/infer`，审计时没有发现 8001 监听服务。
- 用户认证：SQLite `runs/auth/users.sqlite3`，保存用户、会话和一次性密码重置凭据。
- 长期记忆：MemoryStore 使用 SQLite；代码支持可选 Redis 镜像和 PostgreSQL，但当前环境没有配置两者。
- 工作流、运行记录、技能、工具目录：当前仍以 JSON/JSONL 文件持久化。

## 工具描述究竟做什么

工具描述是给模型的“能力说明书”，帮助模型判断何时选择工具。完整工具定义还必须包含唯一名称、JSON 参数结构和后端执行适配器。描述不是操作系统权限，也不是可执行代码。

一个真正的工具循环应为：

1. 后端把当前 Agent 被授权的工具定义发送给支持 tool/function calling 的模型。
2. 模型返回结构化工具调用（工具名和 JSON 参数），而不是假装已经执行。
3. 后端验证 Agent 授权、参数 Schema、用户审批策略和运行沙箱。
4. 后端调用已注册的手机、浏览器、文件系统、MCP 或 HTTP 适配器。
5. 后端把结构化结果作为 tool result 送回模型。
6. 模型根据结果继续推理；可重复多轮，最终输出文本。

当前项目已经完成工具目录、Agent `tool_ids` 授权和工具事件展示，但标准执行器尚未实现上述第 1～5 步，因此现在登记描述不会产生真实电脑操作。

## 生产环境仍需接入

- 邮件服务：SMTP、Amazon SES、SendGrid 等，用于发送忘记密码链接。启用后必须设置 `AUTH_EXPOSE_RESET_TOKEN=0`。
- 真实工具适配器：建议使用 MCP Server 或后端白名单函数；每个适配器明确参数 Schema、权限、超时和审计策略。
- 共享业务数据库：单机可继续 SQLite；多实例部署建议将用户、工作流、运行、工具和审计迁移至 PostgreSQL。
- Redis：用于多实例会话、任务队列、SSE 事件广播和限流。
- 对象存储：如任务需要文件上传、制品或大模型生成文件，接入 S3/MinIO。
- HTTPS 与反向代理：生产环境使用 Caddy/Nginx/云网关，并避免在查询参数长期传递会话令牌。
