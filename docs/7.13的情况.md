# 端-边-云自适应调度整体架构文档
## 一、完整执行整体流程
节点即将执行
1. HookManager 构造 `ResourceRequest`
2. TaskGate 生成 `TaskProfile`
3. TrustedWorkspacePolicy 判断敏感数据流向
4. ResourceMonitor 提供端/边/云实时状态
5. AdaptiveResourceScheduler 选择 DEVICE / EDGE / CLOUD
6. 生成 `ModelSplitPlan`
7. ResourceAllocation 注入节点 state
8. 节点根据调度结果调用对应 executor
9. 执行失败时反馈给 `MutableResourceMonitor`
10. 必要时重新调度

## 二、分层模块说明
### 1. 调度接入层
对应文件：`engine/hooks.py`
- Graph 构造 `NodeContext`，基于上下文信息构造 `ResourceRequest`，作为整条调度链路统一入口，用于描述任务所需资源规格。

### 2. 任务画像层
对应文件：`engine/modules/scheduling/gate.py`
抽象能力：`TaskGate`，用于评估任务种类、难度、实时性、敏感等级，提供两类实现：
1. `HeuristicTaskGate`：默认实现，启发式规则判断，适合本地测试
2. `OpenAITaskGate`：大模型驱动实现，通过真实LLM完成任务评估

输入：节点 metadata、运行时 state、用户输入、节点描述、系统提示词
输出：`TaskProfile`（任务完整画像）

### 3. 可信工作区策略层
对应文件：`engine/modules/scheduling/policy.py`
可信规则：
- DEVICE（端）、EDGE（边缘）默认属于可信工作区
- CLOUD（云端）默认不可信

调度约束逻辑：
1. 标记 `CONFIDENTIAL` / `SECRET` 的敏感任务，优先分配至可信层级
2. 若任务复杂度极高、最优解为云端，但数据敏感且无人工审计通道，则退回可信边缘执行
3. 系统仅存在云端资源、无任何可信节点时，保留云端调度选项

输出：资源可信约束、是否需要人工审计标记，用于过滤调度候选资源

### 4. 端-边-云资源画像层
对应文件：`engine/modules/scheduling/_types.py`
统一资源描述结构：`ResourceProfile`
静态资源预设画像：
| 资源层级 | 特性 | 适配任务复杂度 | 可信属性 |
|--------|------|--------------|--------|
| DEVICE 端侧 | 低延迟、低成本 | low / medium | 可信 |
| EDGE 边缘 | 较低延迟 | medium / high | 可信 |
| CLOUD 云端 | 算力最强 | high / extreme | 默认不可信 |

输出：静态资源能力集合，用于判断资源理论承载上限

### 5. 资源状态层
对应文件：`engine/modules/scheduling/monitor.py`
四类监控实现：
1. `NoOpResourceMonitor`：默认空实现，直接使用静态资源画像，不做实时探测
2. `StaticResourceMonitor`：固定静态资源状态，用于测试演示
3. `SystemResourceMonitor`：轻量探测本机/HTTP节点实时负载
4. `MutableResourceMonitor`：闭环反馈监控，记录执行失败，动态更新资源状态，影响下一轮调度

输出：`ResourceStatus`（运行时资源可用状态、限流、错误率、实时延迟）

### 6. 自适应选择策略层
对应文件：`engine/modules/scheduling/scheduler.py`
#### 任务优先级调度规则
- 强实时任务：DEVICE → EDGE → CLOUD
- 高复杂度任务：CLOUD → EDGE → DEVICE
- 敏感任务：优先可信层级；非可信层级需人工审计放行
- 普通任务：基于 `tier_preference` 与资源综合能力择优

#### 调度输出产物
1. `SchedulingDecision`：调度决策结论
2. `ResourceAllocation`：资源分配明细，注入节点 `__resource_allocation__`
3. `SchedulingTrace`：调度完整追踪日志

业务节点读取 `__resource_allocation__`，区分调用端/边/云执行器。

### 7. 模型切分层
调度不直接简单指定资源层级，而是生成精细化 `ModelSplitPlan`（模型切分执行链路），拆分任务多阶段分发至不同层级，示例：
1. 公开高复杂任务：`local_gate -> cloud_inference`
   本地门控校验，高算力推理交由云端
2. 敏感复杂邮件任务：`local_gate -> trusted_redaction -> edge_inference`
   本地任务判定 → 可信工作区脱敏 → 边缘完成推理

输出：`ModelSplitStep` 步骤列表，定义各阶段执行位置

### 8. 安全脱敏与审计层
对应目录：`engine/modules/security/`
触发条件：`ModelSplitStep` 包含 `trusted_redaction` 脱敏节点
执行逻辑：
1. HookManager 捕获原始任务 payload
2. 扫描敏感字段：API Key、Token、私钥、邮箱、手机号、银行卡号等
3. 生成脱敏后数据、审计包，注入节点 state：`__redaction__`、`__audit_pack__`
4. 节点执行时使用脱敏数据，原始敏感信息不直接外传至非可信资源

### 9. 执行适配与反馈闭环层
1. 调度产出 `ResourceAllocation` 后，通过 `ExecutorRegistry` 根据 tier 匹配对应端/边/云执行器
2. `ResilientInferenceRunner` 统一处理推理执行、失败重试
3. 执行成功：返回推理结果
4. 执行失败：错误信息写入 `MutableResourceMonitor`，更新全局资源状态，触发二次重调度

## 三、层间流转完整流程表
| 顺序 | 流转阶段 | 输入 | 处理内容 | 输出 | 下游使用方式 |
|------|--------|------|---------|------|------------|
| 1 | Graph 节点即将执行 | 节点名、节点 metadata、当前 state、全局 config | HookManager 拦截节点前置流程，收集调度上下文 | ResourceRequest | 整条端边云调度链路统一入口 |
| 2 | 任务画像层 | ResourceRequest | TaskGate 评估任务类型、实时性、敏感等级、复杂度、可信需求 | TaskProfile | 调度器依据画像定义资源偏好 |
| 3 | 可信工作区策略层 | TaskProfile、资源可信属性 | TrustedWorkspacePolicy 校验敏感数据跨可信层级放行规则 | 可信约束、人工审计标记 | 过滤调度候选资源池 |
| 4 | 资源画像层 | 端/边/云静态配置 | ResourceProfile 标准化各层级算力、延迟、成本、可信度、复杂度上限 | 静态资源能力集合 | 校验资源理论承载能力 |
| 5 | 资源状态层 | 实时资源探测结果、历史执行失败记录 | ResourceMonitor 输出动态运行状态：可用性、限流、错误率、实时延迟 | ResourceStatus | 剔除不可用/限流资源 |
| 6 | 自适应调度层 | TaskProfile、可信约束、ResourceProfile、ResourceStatus | AdaptiveResourceScheduler 综合实时性、敏感度、算力、负载、成本、延迟择优分配 | SchedulingDecision、ResourceAllocation | 确定当前节点执行层级 DEVICE/EDGE/CLOUD |
| 7 | 模型切分层 | 调度决策、TaskProfile | 结合安全与算力需求拆分多阶段执行链路 | ModelSplitStep 步骤列表 | 定义任务各阶段运行位置 |
| 8 | 安全脱敏与审计层 | ModelSplitStep、原始 payload、敏感过滤策略 | 存在脱敏节点时扫描敏感字段，生成脱敏数据与审计包 | __redaction__、__audit_pack__ | 节点执行使用脱敏后数据，原始数据不外泄 |
| 9 | 调度结果注入节点 state | ResourceAllocation、脱敏结果、审计包 | HookManager 将调度、安全数据写入节点运行态 | 携带 `__resource_allocation__` 的完整 state | 业务节点读取调度分配信息 |
| 10 | 业务节点执行 | 当前 state、`__resource_allocation__` | 节点读取分配信息，生成对应执行请求 | 标准化执行请求 | 下发至执行适配层 |
| 11 | 执行适配与反馈闭环 | 执行请求、ResourceAllocation | ExecutorRegistry 匹配对应层级执行器，统一容错推理运行器执行 | InferenceResult | 成功直接返回结果；失败进入反馈链路 |
| 12 | 失败反馈重调度 | 失败 InferenceResult | 将异常类型（云端限流、边缘不可用等）写入 MutableResourceMonitor | 更新后的 ResourceStatus | 下一轮调度自动规避异常资源，重新分配 |
