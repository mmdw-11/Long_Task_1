# 实验五 v3：两组结构化低熵通信正式设计

## 1. 目标与两组对照

本实验验证：在保持任务关键事实不丢失的前提下，结构化通信能否减少重复错误传播、跨 Agent token 负载和最终错误采纳。

| 组别 | 通信方式 |
|---|---|
| B0 `baseline_full_history` | 上游 messages 追加到共享历史，后继读取全文 |
| Ours `structured_gate` | 定向 MessageCapsule、fact/claim 身份、冲突标记、重复剪枝、新 claim 保护、256-token 单边预算与字段感知压缩 |

本次正式主表只有以上两组；不再把 `structured_no_gate` 作为正式方法。

## 2. 后端通信合同

每条 Capsule 必须包含 `claim_id`、`fact_key`、`kind`（claim/evidence/conflict/summary）、`claim`、evidence、goal、subtask、provenance 与预算。

门控顺序：

```text
expired                -> prune
constraint/conflict    -> deliver
new fact_key/claim_id  -> deliver as novel_claim_protected
same fact + same claim -> prune as redundant
other messages         -> contribution score decides deliver/compress/deprioritize
```

StateDelta 不携带 `messages`、`capsule` 或 `__*` 运行时字段，避免通信包递归嵌套。相同 `fact_key` 下的不同 claim 会生成 conflict 事件，二者都投递，供 aggregator/writer 按 evidence confidence 决策。

## 3. 100 条数据集

数据集 `communication_low_entropy_100_v3.jsonl`：

| 家族 | N | 拓扑/信息条件 | 主要指标 |
|---|---:|---|---|
| fanin | 40 | 2–5 个 relay 向 aggregator 发送同一错误 claim | 错误放大、重复剪枝 |
| multihop | 20 | 分叉后汇聚到中继，再与直接路径共同到达 aggregator | 长程错误级联 |
| independent | 20 | 2–4 个不同 fact_key 的独立事实 | critical recall、FPR |
| conflict_long | 20 | 低置信错误 claim 与高置信正确 evidence 冲突，含长描述 | 压缩、冲突、最终准确率 |

所有样本在两组中使用同一个模型、温度、图、payload、gold 和注入位置；relay payload 在真实 LLM relay 调用结束后冻结，避免模型随机改写成为组间混杂因素。

## 4. 指标与预注册门槛

| 指标 | 判据 |
|---|---|
| Aggregator prompt token（主效率指标） | Ours 比 B0 至少低 25% |
| 单条 relay payload token（诊断项） | 允许协议字段开销；必须与实际 prompt token 联合解释 |
| fanin 重复剪枝率 | ≥ 90% |
| independent critical fact recall | ≥ 95% |
| independent FPR | ≤ 5% |
| conflict_long compression events | 大于 0，且关键 fact 不丢失 |
| conflict_long writer accuracy | 不比 B0 低超过 5 个百分点 |
| conflict_long false-claim adoption | Ours 低于 B0 |

`error_amplification_factor` 定义为 aggregator 收到的初始错误 claim 副本数；它随 2–5 relay 扇入和多跳结构变化，不再被固定为 2→1。旧 Writer ECR 被删除：它只衡量 writer 是否看见错误文本，不衡量是否采纳错误。替代为最终任务准确率与 false-claim adoption。

## 5. 逐步运行

在 `D:\PythonProject\long_task_1\long_task_1`：

```powershell

D:\Python\python.exe -m pytest tests/test_communication.py tests/test_communication_error_cascade_experiment.py -q --basetemp .pytest-lowentropy-v3

# B. 不调用模型：生成冻结数据集和 hash

D:\Python\python.exe examples/experiments/run_communication_error_cascade.py --bootstrap-from-env --subsets fanin multihop independent conflict_long --per-subset 1
```

C 步骤应出现：所有 run `status=valid`；fanin 有 `redundant_pruned=1`；independent 的 `critical_fact_recall=1`、`false_prune=0`；conflict_long 有 `compression_events>0`，并输出 writer JSON。若不满足，不启动全量。
