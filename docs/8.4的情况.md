# 8.4 的情况

## 一、当前问题

之前的任务目标语义漂移检测主要依赖 embedding 余弦相似度：把最近工具摘要、next action、pending step 与顶层 `original_goal` 做相似度对比，连续低于阈值就判定为偏离。

这个方案在长任务里容易误判。原因是中途动作经常只是最终目标的一小部分，例如“补一个测试”“修改某个配置字段”“新增一份文档”。这些子步骤和顶层目标的字面或向量相似度可能不高，但它们仍然属于合理的任务拆解路径。因此，任务目标漂移不能只靠“当前局部内容 vs 顶层目标”的向量距离来决定。

## 二、改造目标

这次将漂移拆成两类处理：

1. 结构性死循环漂移继续走规则检测。
   - 重复节点
   - pending 堆积
   - 长期无进展
   - 重复输出摘要
   - 重复 raw_ref 资源
   - 重复工具调用
   - 重复文件操作

2. 任务目标语义漂移改为 LLM 判定。
   - 只判断当前动作是否脱离任务主线。
   - 不判断实现细节是否正确。
   - 不传全部历史，只传顶层目标、顶层任务计划、当前动作内容。

## 三、阶段 1：最小兼容改造

核心实现集中在 `engine/modules/context/drift.py`。

新增了三类接口：

- `TaskDriftJudgeResult`
  - `is_task_drift: bool`
  - `reason: str`
  - `raw: str = ""`

- `TaskDriftJudge`
  - 统一抽象 LLM 漂移判定器。
  - 输入为 `original_global_goal`、`task_plan_list`、`current_step_content`。

- `OpenAITaskDriftJudge`
  - 基于 OpenAI-compatible Chat Completions API。
  - 默认读取 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。
  - 要求模型只返回 JSON：`{"is_task_drift": bool, "reason": "..."}`

`DriftDetector.detect()` 现在先执行原有结构性规则，再进入任务目标语义漂移分支。结构性规则命中后仍然直接记录 `ContextDrift`，不会等待 LLM 复核。

LLM prompt 使用紧凑模板：

```text
【整体顶层任务目标】
{original_global_goal}
【前期整体任务拆解规划步骤】
{task_plan_list}
【当前Agent正在执行的动作、输出内容】
{current_step_content}

请你只输出JSON格式：
{"is_task_drift": bool, "reason": "简短原因说明"}
```

如果 LLM 返回非法 JSON，系统会保守判定为不漂移，并保留 reason/raw 便于排查，避免检测器因为模型格式问题误杀正常执行。

## 四、阶段 2：长上下文优化

语义漂移判定不再塞完整历史。

当前动作内容按优先级生成：

1. 最近工具或节点摘要 `tool_summaries[-1].short_summary`
2. 当前 `ledger.next_action`
3. 最近 pending step

顶层上下文只取：

- `ledger.original_goal`
- `ledger.current_plan`
- 当前动作内容

这样可以控制 token 成本，也让模型专注判断“是否脱离主线”，而不是被历史细节拖偏。

## 五、阶段 3：混合策略

新增 `semantic_drift_mode`：

- `off`：默认值，不启用任务目标语义漂移检测，避免默认运行产生模型调用。
- `llm`：直接由 LLM 判断任务目标漂移。
- `hybrid`：embedding 只做节省成本的前置放行，高相似度直接判无漂移，其余交给 LLM。
- `embedding`：保留旧的纯 embedding 兼容模式。

新增阈值：

- `goal_similarity_high_threshold`：默认 `0.85`，hybrid 下高于该值直接放行。
- `goal_similarity_low_threshold`：默认 `0.35`，保留为策略配置字段，低/中相似度统一交给 LLM 复核。
- `goal_drift_window`：继续用于选取最近动作窗口。

新增缓存：

- `semantic_drift_cache_enabled` 默认开启。
- 使用 顶层目标 + 计划 + 当前动作内容 的稳定 hash 做进程内缓存。
- 相同步骤内容可复用 LLM 判断结果，减少重复调用。

## 六、配置与导出

`engine/modules/context/policy.py` 已新增并透传语义漂移配置：

- `semantic_drift_mode`
- `goal_similarity_high_threshold`
- `goal_similarity_low_threshold`
- `semantic_drift_cache_enabled`

`ContextPolicy.build_drift_detector()` 支持显式注入：

- `embedding_model`
- `task_drift_judge`

不会在读取配置文件时创建真实 API judge，避免测试或普通启动阶段发生网络副作用。

`engine/orchestrator.py` 已增加自动装配逻辑：

- 当 `semantic_drift_mode` 是 `llm` 或 `hybrid`；
- 并且环境变量里存在 `TASK_DRIFT_API_KEY`、`TASK_DRIFT_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_BASE_URL` 之一；
- `Orchestrator.set_context_policy()` 会自动创建 `OpenAITaskDriftJudge` 并注入 `DriftDetector`。

真实模型推荐配置方式：

```powershell
$env:TASK_DRIFT_BASE_URL="http://127.0.0.1:8000/v1"
$env:TASK_DRIFT_API_KEY="not-needed"
$env:TASK_DRIFT_MODEL="你的模型名"
```

如果使用 OpenAI 官方接口：

```powershell
$env:TASK_DRIFT_API_KEY="你的 API Key"
$env:TASK_DRIFT_MODEL="gpt-4o-mini"
```

然后在 context policy 中打开：

```yaml
semantic_drift_mode: llm
```

或使用混合模式：

```yaml
semantic_drift_mode: hybrid
goal_similarity_high_threshold: 0.85
goal_similarity_low_threshold: 0.35
```

公共导出已补齐：

- `TaskDriftJudgeResult`
- `TaskDriftJudge`
- `OpenAITaskDriftJudge`

## 七、测试结果

本次调整保留了原有结构性漂移测试，并新增了 LLM 语义漂移专项测试：

- 重复节点漂移仍可检测。
- 重复摘要漂移仍可检测。
- 重复文件操作漂移仍可检测。
- 合法子任务由 fake LLM judge 判定为不漂移。
- 无关旅行闲聊动作由 fake LLM judge 判定为漂移，并写入 `ContextDrift`。
- hybrid 模式下高相似度会跳过 LLM judge。
- 非法 JSON 解析失败时不会误判漂移。
- `ContextPolicy.from_file()` 能加载新增字段并构造 detector。
- `Orchestrator.set_context_policy()` 在语义漂移开启且环境变量存在时，会自动装配真实 LLM judge。
- 未配置模型环境变量时，即使 policy 开启 `llm`，也不会创建真实 judge，保持离线安全。
