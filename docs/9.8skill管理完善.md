# 9.8 Skill 管理完善

## 一、本次改了什么

本轮将原先分散的 Skill 市场、安装入口、个人 Skill 和技能治理流程，整理为一套统一的 Skill 管理体系。核心目标是让用户能够清楚地区分平台 Skill、自己维护的 Skill 和真正可供应用绑定的 Skill，同时补齐从创建到运行时语义检索的完整链路。

前端统一为三个一级标签：

- **Skill 市场**：展示平台维护的只读 Skill。用户只能查看、安装或复制，不能直接编辑和删除。
- **我的 Skill**：展示用户创建、复制或导入的 Skill，并管理草稿、检查、发布和后续修订。
- **已安装**：展示当前可以绑定到智能体或工作流的 Skill，包括已安装的平台 Skill和用户自己已发布的 Skill。

同时修复了列表搜索、分类筛选、来源筛选、状态筛选、移出个人库请求、编辑弹窗层级、发布后访问失效草稿 ID、同名版本重复平铺等问题。

## 二、Skill 生命周期

用户 Skill 采用以下生命周期：

```text
新建或导入
    ↓
保存草稿
    ↓
检查内容
    ↓
检查通过
    ↓
手动发布
```

草稿不能绑定到应用。当前“检查内容”会检查正文长度，以及是否包含“适用场景”“执行步骤”“校验方式”等必要章节；运行生成的 Skill 还要求保留来源运行记录，便于追溯。

编辑已经发布的 Skill 时，不直接覆盖线上内容，而是创建或复用一个修订草稿。线上版本继续供已有应用使用，直到新版本检查通过并正式发布。管理页把线上版本和修订草稿组织成同一个逻辑 Skill，卡片提供“查看线上版”和“查看新版本”入口；放弃修订只删除新版本，不影响线上版本。

发布修订时，后端把修订内容写入原 Skill、递增正式发布版本、删除临时修订记录并重建语义索引。前端直接使用发布接口返回的新记录，避免再次请求已经删除的草稿 ID。

平台内置 Skill 始终显示为“平台维护、只读、已发布”。用户需要修改时使用“复制到我的 Skill”，复制结果从个人草稿开始，不会改变平台版本。

## 三、安装关系与权限

新增用户级安装关系，记录：

- `user_id`
- `skill_id`
- `installed_at`
- `enabled`

安装操作是幂等的，同一个用户重复安装不会产生重复记录。移出个人库只删除用户安装关系，不删除平台 Skill。正在被应用引用时，界面会展示影响范围并限制危险操作。

Skill 接口统一返回来源、权限、安装状态、分类、场景、关键词、正式版本、草稿版本和使用数量。前端不再仅根据 `visibility` 推测用户是否能够编辑或删除。

智能体和工作流的 Skill 选择器只允许选择：

- 已安装的平台 Skill；
- 当前用户已经发布的 Skill。

## 四、搜索与筛选

管理页支持名称、简介和标签模糊搜索，并按当前标签提供分类、来源及生命周期状态筛选。分类从实际接口数据动态生成，切换详情和刷新列表时不会破坏当前管理结构。

普通列表搜索与“检索命中测试”已经分开：

- 列表搜索用于快速找到管理对象；
- 检索命中测试用于验证一段真实任务在运行时会命中哪些 Skill。

## 五、BGE-M3 语义检索

新增 SQLite Skill 向量索引。每个已发布 Skill 会由以下内容生成检索摘要：

- 名称和简介；
- 主分类、适用场景和关键词；
- 标签；
- SKILL.md 的主要正文。

摘要通过本地 BGE-M3 生成 1024 维归一化向量。当前自动发现的模型目录为：

```text
runs/router_learning/bge_m3/BAAI--bge-m3
```

模型适配同时兼容不同 FlagEmbedding 版本返回的 `dense_vecs` 和 `dense_embeds` 字段。向量及内容哈希保存在 `runs/skills/skill_index.sqlite3`，Skill 内容或正式版本变化后会重新建索引。

检索支持三种模式：

- **仅规则**：依据名称、标签、简介和正文的关键词信号评分；
- **仅语义**：依据 BGE-M3 余弦相似度评分；
- **混合检索**：综合语义分、规则分和应用绑定上下文。

混合基础分为：

```text
0.65 × 语义分 + 0.25 × 规则分 + 0.10 × 上下文分
```

最终结果不会低于有效的原始语义分，避免“我想出去玩”已经与“旅行计划”语义相关，却被混合权重再次压低到阈值以下。规则检索保留少量中文同义表达作为模型不可用时的降级能力。

正常语义与混合检索阈值为 `0.5`。检索页面展示语义、规则、上下文及可选模型重排分数，并明确标识结果是否会注入运行上下文。

## 六、可选模型重排

检索测试可选择一个已经配置并测试成功的模型连接做二次重排。流程为：

1. 规则和 BGE-M3 先召回候选；
2. 低于最终阈值的候选不会在重排前被过早删除；
3. 模型根据任务、Skill 名称、简介和适用场景判断相关性；
4. 最终分按 `0.7 × 原检索分 + 0.3 × 重排分` 计算；
5. 模型不可用时保留原检索结果，并返回明确的降级原因。

当前正式运行默认使用混合检索，模型重排主要用于检索测试，避免每个节点都产生额外模型费用和延迟。

## 七、运行时注入与观测

正式运行时默认选取前三个符合范围和阈值的 Skill，注入内容总长度限制为约 4000 字符。存在具体智能体或工作流节点上下文时，只从该应用或节点已经绑定的 Skill 中选择。

运行观测新增以下事件：

- Skill 检索开始；
- 语义检索降级；
- Skill 被选中；
- Skill 内容被注入；
- 命中分数和正式版本。

检索测试页同时区分“全局向量索引数量”和“当前用户可检索数量”。全局索引正常不代表平台市场中的全部 Skill 都已安装；平台 Skill 必须先加入个人库才会成为运行候选。

## 八、主要接口

- `GET /api/skills`：按 scope、关键词、分类和状态读取 Skill。
- `POST /api/skills`：创建个人草稿。
- `PUT /api/skills/{skill_id}`：编辑草稿，或为已发布 Skill 创建/复用修订。
- `POST /api/skills/{skill_id}/validate`：检查内容。
- `POST /api/skills/{skill_id}/publish`：发布正式版本。
- `POST /api/skills/{skill_id}/copy`：把平台 Skill 复制为个人草稿。
- `POST /api/marketplace/skills/{slug}/install`：安装到个人库。
- `DELETE /api/marketplace/skills/{slug}/install`：移出个人库。
- `POST /api/skills/search`：执行规则、语义或混合检索。
- `GET /api/skills/index/status`：读取向量索引状态。
- `POST /api/skills/index/rebuild`：重建全部可见 Skill 索引。
- `POST /api/skills/{skill_id}/index`：重建单个 Skill 索引。

## 九、测试与验证

新增的回归测试覆盖：

- 用户级安装与重复安装幂等性；
- 平台 Skill 只读和复制为草稿；
- 草稿检查、发布和正式版本递增；
- 编辑已发布 Skill 时复用同一个修订草稿；
- 发布修订后线上 Skill 更新；
- 长正文不会稀释规则匹配分；
- 常见中文改写能够召回相关 Skill；
- BGE-M3 语义分和混合分拆解；
- 没有字面重叠时保留有效语义命中；
- 灰度元数据变化不制造新的内容版本。

前端使用 TypeScript 编译和 Vite 生产构建验证，后端使用 Skill 管理、检索和治理测试验证。
