# 8.28 项目情况

## 一、当天完成的主要内容

### 1. 合并远程 MCP 更新

- 后端和前端均在 `dev-sje` 分支合并了最新 `origin/main`。
- 后端保留并接入了远程新增的 MCP 发现、连接导入、工具同步和执行能力。
- 前端保留当前分支的页面布局和交互，同时补入 MCP、OpenAPI、同步和测试等入口。
- 后端原有运行日志 `server.out.log` 属于本地运行产生的用户文件，没有加入功能提交。

### 2. 工具配置改为右侧抽屉

- 智能体配置页不再直接展示全部内置工具，只显示当前智能体已经选择的工具。
- “添加工具”使用与 Skill 相同的右侧抽屉交互。
- 抽屉可以搜索、筛选和选择内置工具、MCP 工具、OpenAPI 工具。
- 外部 MCP/OpenAPI 接入成功后会刷新列表并选中新工具。
- 工具的编辑、测试、同步、启停和删除仍放在工具管理页完成。

### 3. Skill 选择和文件导入调整

- 智能体配置页外部的 Skill 列表只展示本次智能体已选择使用的 Skill，不再展示所有已安装 Skill。
- Skill 抽屉中完成添加后，对应 Skill 才会显示在智能体配置页。
- 删除了重复的“上传 Skill”入口，市场和自定义仍作为抽屉内的主要入口。
- 统一文件导入接口支持 `.zip` 和 `.md`。
- `.zip` 保留安全解包、路径、数量、大小和扩展名检查；`.md` 按单文件 Skill 校验和导入。
- 修复重复上传相同 Skill 时产生多条同名记录的问题。

### 4. 主库和参考库记忆模型

- 应用保留 `memory_bank_ids`，新增 `primary_memory_bank_id`。
- 每个应用最多指定一个可写主库，其余绑定库为只读参考库。
- 主库和参考库都参与检索，但运行产生的新长期记忆只能写入主库。
- 旧应用没有指定主库时，将第一个已绑定记忆库作为主库。
- WORKING、TASK、PROJECT、GLOBAL 是每个记忆库内部的四级作用域，不是四个独立记忆库。

## 二、8.28 新增的长短期记忆能力

### 1. 应用记忆配置

应用增加结构化 `memory_config`，当前包含：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `short_term_enabled` | `true` | 是否启用当前会话短期记忆 |
| `context_rounds` | `8` | 携带最近多少轮完整对话，范围 0–30 |
| `context_token_budget` | `0` | 0 表示自动预算，也可手动设置 |
| `rolling_summary_enabled` | `true` | 超出预算时是否生成滚动摘要 |
| `long_term_enabled` | `true` | 是否启用长期记忆检索和沉淀 |
| `memory_top_k` | `5` | 长期记忆最大召回数量，范围 1–20 |
| `wakeup_level` | `standard` | 静默、标准、深度、恢复四档 |
| `auto_write` | `true` | 是否自动沉淀长期记忆 |
| `deduplicate` | `true` | 是否阻止重复长期记忆 |
| `sensitive_filter` | `true` | 是否阻止密钥、令牌、密码等敏感内容 |

旧应用没有 `memory_config` 时会在读取时使用默认值，不要求迁移原 JSON 文件。

### 2. 持久化短期会话

- 新增 `ConversationStore`，会话以 `conversation_id` 区分并持久化保存。
- 一次会话会保存用户消息、最终助手回复、滚动摘要和 token 估算。
- 新会话之间完全隔离。
- “清空”只删除当前会话的短期消息和摘要，不影响长期记忆库。
- 应用运行请求支持可选 `conversation_id`；没有传入且短期记忆开启时，后端会自动创建会话。

现有接口：

- `POST /api/apps/{app_id}/conversations`：创建会话。
- `GET /api/apps/{app_id}/conversations`：查询应用会话列表。
- `GET /api/apps/{app_id}/conversations/{conversation_id}`：查询会话详情。
- `DELETE /api/apps/{app_id}/conversations/{conversation_id}`：清空该会话短期内容。

### 3. 上下文轮数和压缩

- 运行时携带最近 `context_rounds` 轮用户与助手消息。
- `context_rounds=0` 表示不携带历史消息。
- 超出 token 预算时，优先保留当前问题和最近两轮完整对话。
- 更早的消息会压缩到滚动摘要，不再重复占用完整上下文。
- 上下文会作为独立的“短期会话上下文”注入 Agent prompt。
- 运行记录 metadata 会保存 `conversation_id` 和 `context_usage`，其中包括实际轮数、token 估算和是否压缩。

### 4. 长期记忆治理

- 不再把所有节点输出无条件写入长期记忆。
- 每轮成功结束后，从用户输入中识别稳定偏好、长期要求和项目决策候选。
- 自动写入只允许进入主库的 PROJECT 层。
- GLOBAL 层不会被自动写入，后续只能由记忆管理页人工提升。
- 参考库永久只读，不会被当前应用运行修改。
- 完全相同的候选会被去重并记录为 `ignored`。
- 密码、API Key、Token 和明显密钥内容会被敏感过滤器拦截并记录为 `blocked`。
- 成功新增会记录为 `added`，审计记录包含应用、主库、run、conversation、候选内容、动作、原因和时间。

现有接口：

- `POST /api/apps/{app_id}/memory-preview`：预览短期上下文、绑定库和预计召回记忆，不调用模型。
- `GET /api/apps/{app_id}/memory-audit`：查询应用长期记忆判断审计。

### 5. 前端配置和调试界面

- 记忆配置参考百炼的基础布局。
- 普通区域展示短期记忆开关、0–30 轮滑块和数字输入、长期记忆开关、主库和参考库选择。
- token 预算、滚动摘要、长期召回数量、唤醒级别、自动写入、去重和敏感过滤放在折叠的高级设置中。
- 调试区显示当前配置的上下文轮数、估算 token 和是否发生摘要压缩。
- 调试区支持“清空”和“新会话”；两者均不会删除长期记忆。
