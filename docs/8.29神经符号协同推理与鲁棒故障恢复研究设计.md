# 神经符号协同推理与鲁棒故障恢复研究设计

## 1. 能力审计

原系统可复用 graph 超步执行、条件边、hooks、checkpoint、FailureTrace、context ledger、时态证据记忆、MessageCapsule、资源调度器和 SSE 事件流。但 planner 仅生成字符串 TODO；RuleEvaluator 只检查输出键、文件和父节点认可；默认 routing 是 passthrough，recovery 是 `NoOpRecoveryStrategy → ABORT`。工具失败常被降格为普通结果，timeout、消息/证据缺失、角色失效和副作用重放没有统一语义。系统没有 typed IR、规则库、SMT、unsat core 或 counterexample repair。因此这些能力原先是工程骨架，不能作为神经符号或恢复研究贡献。

## 2. 主流程

```text
LLM / deterministic generator
          │ strict schema
          ▼
        PlanIR ───────► SymbolicPlanValidator ── SAT ─► verified graph execution
          ▲                       │
          │                       └─ UNSAT/INVALID + unsat core/witness
          │                                      │
          └──────── PlanRepairer ◄── counterexample MessageCapsule

node/tool/resource failure → FailureContext → PolicyRecoveryStrategy
                              │
                              ├ retry / fallback / takeover / migrate / degrade
                              ├ compensate → checkpoint/replan
                              └ human_review for unsafe replay
```

`PlanIR` 包含目标、子任务、依赖、时长、角色、资源、前置/效果、验收条件、fallback、幂等类型、硬/软约束和风险。只有 `ValidationResult.passed` 的 revision 才执行。确定性 validator 始终可用；安装 `.[neurosymbolic]` 后 `backend=auto|z3` 使用 Z3 命名约束和 unsat core。

## 3. 核心算法

### 3.1 Counterexample-guided planning

```text
plan ← Generator(goal, context)
for revision in 0..R:
    result ← ValidateDAGRolesResourcesTimePolicies(plan)
    if Z3 enabled: result ← SMTCheckWithNamedAssumptions(plan)
    if result is SAT: return VERIFIED(plan, result)
    cex ← MinimalWitnessOrUnsatCore(result)
    emit Capsule(validator → planner, constraint_delta=cex)
    plan ← Repairer.revise(plan, cex)  # new revision only
return PAUSE(plan, result)
```

确定性后端检查重复/缺失依赖、环、自依赖、角色可用性、资源容量、precedence、mutex、deadline、硬策略和 required evidence。Z3 后端用整数 start/end 编码依赖、deadline 与互斥，并返回 tracked assumptions 的 core。LLM 不能自我宣称 verified，也不能绕过 validator。

### 3.2 Side-effect-aware recovery

```text
failure ← Classify(exception, node metadata, attempts, resource state)
if non_idempotent and no compensation: HUMAN_REVIEW
if compensatable: COMPENSATE before replay
if transient and attempts < budget: bounded RETRY(backoff+jitter)
else select explicit fallback/tool/model/node/takeover/migration/degrade
if plan invalid or step failed: REPLAN from latest verified checkpoint
else ABORT
record failure_detected, recovery_planned, attempt and terminal result
```

恢复决策由 `FailureKind × attempt × side_effect_class × node metadata` 决定。默认只允许 `read_only/idempotent` 重放；`compensatable` 先补偿；无补偿的 `non_idempotent` 必须人工确认。所有动作有界，避免 retry/fallback 环。

## 4. 状态、checkpoint 与事件

- `__plan_ir__`、`__plan_validation__`、`__plan_revisions__`：计划 revision 和证明结果。
- `__failure_context__`、`__recovery_trace__`：统一故障与 recovery episode。
- `__side_effect_journal__`：已提交副作用、幂等键和补偿状态。
- checkpoint metadata 保存通信水位线、verified run 和 recovery episode 水位线；历史 trace 不因逻辑恢复删除。
- 事件：`plan_verified/rejected`、`symbolic_counterexample`、`failure_detected`、`recovery_planned`、`fallback_selected`、`checkpoint_resumed`、`plan_revised`、`degrade_entered`、`takeover_assigned`、`recovery_succeeded/failed`。

## 5. 实验协议

固定 seed=42。规划消融为 natural-language、structured IR、rule validation、Z3+repair；指标为 parse rate、constraint satisfaction、DAG consistency、hard violation、repair success、revision count、solver/LLM latency 与 token overhead。恢复消融为 abort、retry-only、policy、policy-without-checkpoint；指标为 task completion、recovery success、MTTR、rollback distance、extra attempts/tokens、fallback count、degraded success、duplicate-side-effect rate 和 unrecovered fault rate。

运行：

```bash
python examples/experiments/run_neurosymbolic_recovery_experiment.py
```

输出 `summary.json`、`episodes.jsonl`、`report.md`。离线脚本只验证算法链与指标格式，不冒充真实 LLM 结果；缺少 Z3/模型凭据时标为 skipped。

## 6. 研究来源与接入判断

- [Logic-LM](https://github.com/teacherpeterpan/logic-llm)：借鉴 formalize–solve–feedback–self-refine，任务代码不直接嵌入 runtime。
- [LINC](https://github.com/benlipkin/linc)：借鉴语义解析与符号推理解耦；其数据/推理框架不直接集成。
- [KnowAgent](https://github.com/zjunlp/KnowAgent)：借鉴 action knowledge 约束轨迹；不复制训练流程。
- [Z3](https://z3prover.github.io/api/html/classz3py_1_1_solver.html)：可直接安装的 optional solver，用于 named assumptions 与 unsat core。
- [OR-Tools scheduling](https://developers.google.com/optimization/scheduling)：适合后续 job-shop/大规模资源优化，本版不引入第二个重依赖。
- [ReliabilityBench](https://arxiv.org/abs/2601.06112)：借鉴 controlled tool/API fault 与 end-state correctness。
- [Apache Airflow retries](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/tasks.html)：采用有界 retry 与幂等任务原则。

## 7. 论文贡献与第一版边界

可直接写入论文的部分：agent graph typed planning IR；结构检查 + SMT unsat core + counterexample capsule 的闭环；约束和副作用感知的分层恢复；通信/时态记忆/资源迁移/checkpoint 联合状态；可重复故障注入和 recovery episode 指标。

第一版限制：自然语言到 IR 仍依赖模型；基础 validator 不是完整 SMT；standby takeover 依赖声明 capability；业务补偿节点需显式实现；进程间一致 checkpoint 和外部 exactly-once 不在范围内。`checkpoint_resumed` 当前通过受审计的 resume request 进入既有 checkpoint API，而非在节点调用栈中强制倒带。
